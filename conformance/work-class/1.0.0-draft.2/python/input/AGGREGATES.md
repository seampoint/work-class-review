# Bounded aggregate evaluation

Status: DRAFT_NOT_ADOPTED, APPARATUS_ONLY. This document defines the `AGGREGATE_EVALUATOR` role for `seampoint.work-class/1.0.0-draft.2`. The common specification defines canonical JSON, digests and host responsibilities. All other necessary meanings are stated here. The schema is `aggregate.schema.json`; its `$defs` identify the exact closed input, definition, result and refusal shapes. The historical linear candidate remains unchanged.

## AGG-001. Definition and identity

A definition has exactly `schema`, `types` and `aggregate`. Its identity is `digest("aggregate-definition",definition)` under the common domain rule. Types, units, time configuration, window, mappings, observation policy and pending-exposure policy are therefore part of the identity. `evaluate` receives `{kind:"AGGREGATE",request:<input>}` through the new protocol. The complete definition bytes are present in request.definition and their digest is request.definition_digest. The request also binds the exact specification manifest. Neither a type identifier nor an aggregate name can select an external definition.

The first profile supports the five scalar type kinds IDENTITY, STRING, BOOLEAN, INTEGER and DECIMAL. A typed value is `{type_ref,value}`. Type identity is scoped by the complete definition digest plus type_ref. Type arrays are sorted by id in UTF-8 order; IDs are unique. STRING permits any scalar Unicode string, IDENTITY requires a nonempty string, BOOLEAN requires a JSON Boolean. INTEGER and DECIMAL use the common canonical exact-number grammars. A nonnegative flag on those two kinds rejects negative payloads; the flag must be false for other kinds. Unit is null except for a DECIMAL quantity, which may name a nonempty unit. Unit equality is exact and conversion is forbidden. INTEGER quantities and composite group elements are outside this scalar profile and must use a later definition rather than be coerced to strings.

## AGG-002. Reducers, result types and bounds

COUNT and CARDINALITY require a nonnegative INTEGER result type without a unit. SUM requires a nonnegative DECIMAL result type with an explicit unit. SUM adds quantities of that exact type; decimal precision is mathematical, not binary floating point. COUNT's contribution for each selected operation/mapping or selected historical event is the typed result value `"1"`. CARDINALITY declares a nonnull element_type resolving to any supported scalar type; the other reducers require element_type=null. A CARDINALITY contribution is one typed element, not an integer count.

The bound is a nonnegative value of the result type. Operator is LT, LTE, GT or GTE and means the corresponding exact numerical comparison. Definition acceptance establishes its type, not that any proposal satisfies its bound. COUNT begins at zero; SUM at zero of its unit; CARDINALITY at the empty finite set and returns its size. A set accumulator contains full typed values in canonical byte order, with no duplicates. Its final count is a natural-integer string.

## AGG-003. Field mappings and qualifiers

An operation has a nonempty occurrence identifier, step identifier and a sorted, unique array of named typed fields. Occurrences are unique within one input and sort by UTF-8 identifier bytes. Every field is type-checked even if no mapping selects it. Field names are local to the supplied operation, not English descriptions. A mapping contains a unique id, sorted unique nonempty step_ids, qualifier, ordered key_fields and contribution. Mappings sort by id. Its step set selects applicable operations; its qualifier then decides inclusion. Every selected pair of operation and mapping contributes exactly once. Contributions are derived by the evaluator, not supplied as a second caller-controlled projection.

A FIELD operand reads the exactly named field. A LITERAL operand carries an admitted typed value. EQUAL compares equal nominal types and exact values. MEMBER requires every member to have the operand's nominal type; the members form a canonical sorted set. COMPARE accepts equal INTEGER or DECIMAL types and the declared exact comparison. BOOLEAN is its literal truth value. ALL and ANY evaluate every operand, with empty ALL true and empty ANY false; NOT complements its operand. Qualifiers contain no unavailable value, callback or English evaluation. Missing fields, incompatible operands or unsupported expressions are input errors, including beneath a Boolean branch whose other operand already decides the result. Qualifier static structure and literals are checked at definition admission; field availability and operand compatibility are checked against each applicable operation before running its qualifier. A field needed by a false-qualified operation's key or contribution is still required and type-correct; false qualification is not a bypass around input integrity.

For each selected pair, key_fields reads a nonempty tuple whose types equal aggregate.key_types position for position. The order of tuple components matters. COUNT mappings have contribution `{kind:"COUNT"}`; SUM and CARDINALITY mappings name the contribution field and matching kind. Their values have the result or element type respectively. A mapping's contribution kind must equal the aggregate reducer. Mapping field references need not occur in operations for unlisted steps, but all supplied operation fields still have valid types.

## AGG-004. Pending exposure and partitions

The definition explicitly selects INCLUDE_ALL_RESERVED or EXCLUDE_RESERVED. With EXCLUDE_RESERVED, pending must be empty; supplying it is invalid, rather than silently ignoring exposure. INCLUDE_ALL_RESERVED admits pending rows with reservation, mapping, occurrence, key and typed contribution. The mapping exists, the tuple types match, and the contribution has the same kind/type meaning as a newly derived contribution. Pending rows sort by the canonical bytes of `[reservation,mapping,occurrence,key]`; these keys are unique. A pending contribution sharing a new operation's occurrence is invalid. Pending records are host-supplied reservation assertions for this evaluator; the shared-budget transition role derives them from retained state.

PER_ACTION partitions new contributions by `(occurrence,key)` and requires EXCLUDE_RESERVED and no committed source. ROLLING and CALENDAR partition by each distinct grouping tuple in the newly derived contributions. A pending contribution contributes only to a partition with its same tuple. Pending exposure is included regardless of its reservation time; only committed history is filtered through the current window. This is an explicit reservation-counting policy, not a default interpretation of completed-effect limits.

Partition order compares the canonical bytes of `{occurrence,key}`. Occurrence is null for shared-window partitions. The empty new-contribution set produces no partitions and a SATISFIED result after structural, reference, type, binding and limit admission. No observations are requested when there are no partitions. Supplying any observation in that case is invalid. This vacuous result does not authorize an unrelated business operation.

Pending-only tuples do not create partitions and are not invalid merely because this proposal addresses another tuple. They remain retained by their owning ledger and affect a later proposal for their tuple. This preserves evaluation of the partitions affected by the proposed work; it does not clear unrelated reservations.

## AGG-005. Clock and temporal configuration

Definition.time supplies clock_source and precision SECOND or NANOSECOND. The supplied clock source must match. AVAILABLE uses exactly the selected instant precision; UNAVAILABLE uses null. All AVAILABLE observation and event instants use the same precision. Calendar/date validity is checked, not just the schema pattern. No ambient clock or local timezone is consulted.

A nonempty evaluation with UNAVAILABLE clock returns INDETERMINATE partitions with null accumulators/results and sole reason TIME_UNAVAILABLE, including PER_ACTION. Before that outcome, perform all structural, reference, type and directly checkable integrity checks. Query digest and future-time checks needing the absent instant do not run. An empty, admitted proposal remains vacuously satisfied.

Before TIME_UNAVAILABLE, validate every supplied observation's shape, scalar payloads, calendar dates, precision, source identity, coverage ordering, event field/qualifier/contribution types, statistic key/type/accumulator and key inventory, and static freshness declarations. Reject malformed coverage even without a clock. Limits still apply. Skip derived query equality, future as_of, current required-interval containment/equality and freshness evaluation, because these require the absent instant. Distinct reports and conflicting event terminal states are usability findings, so TIME_UNAVAILABLE takes precedence over those conflicts when the clock is absent.

ROLLING duration_seconds is positive, exact and representable on the selected precision grid. The required interval runs from evaluation minus duration through evaluation, with the two explicit endpoint flags. CALENDAR uses its declared timezone and pinned IANA tzdb 2025a. Convert evaluation to local Gregorian date, select the beginning of its declared DAY, WEEK, MONTH, QUARTER or YEAR, then convert that boundary to UTC. WEEK uses the declared starting weekday. YEAR uses the declared fiscal starting month; QUARTER uses successive three-month periods anchored to that month. All calendar fields remain explicit even where a selected period does not use an anchor. Calendar intervals end at evaluation, not at the future period end. The start/end flags apply to this elapsed prefix.

For an ambiguous local boundary, EARLIER_OFFSET chooses the earlier UTC instant and LATER_OFFSET the later one; INVALID refuses. For a nonexistent boundary, SHIFT_FORWARD adds the offset gap to the nominal local boundary, SHIFT_BACK subtracts it, and INVALID refuses. These rules do not reinterpret an input UTC instant. Arithmetic outside years 0001–9999 or a precision-grid overflow gives LIMIT_EXCEEDED. Unsupported timezone or an INVALID boundary choice gives INPUT_INVALID. A UTC host process may implement this arithmetic but cannot choose the policy's zone.

Unused calendar anchors are admitted and remain part of definition identity but have no effect on period selection. Thus two DAY definitions with different valid fiscal anchors have different identities and the same mathematical window for identical clocks.

## AGG-006. Committed source and query

ROLLING and CALENDAR require a nonnull committed_source. PER_ACTION requires null and an empty observations array. The source declares provider, source, freshness, ordered key_fields, qualifier and contribution mapping. Its qualifier has the same exact language as proposal qualifiers. Each ACTIVE event's fields must supply the required key and contribution fields and type-correct qualifier operands. Events count once per source event identity, not once per proposal mapping.

For nonempty shared-window evaluation with an available clock derive the query object with exactly `definition_digest`, `interval` and `keys`. Interval is `{start,end,start_inclusive,end_inclusive}` using the selected precision and calculated bounds. Keys is the canonical sorted unique list of proposal grouping tuples. The request digest is `digest("aggregate-query",query)`. Each observation must bind this digest and the exact declared provider and source. Observations never select a different query, unit, aggregate definition, grouping or endpoint policy.

An observation is UNAVAILABLE, INCOMPLETE, or AVAILABLE. Unavailable/incomplete records retain query identity and evidence reference without fabricated revision or time. AVAILABLE includes nonempty revision, as_of, coverage and either a complete EVENT_SNAPSHOT or a complete STATISTIC bundle. Future as_of is invalid. Coverage is a well-formed interval, start no later than end, within the representable domain. All active event instants and values are validated before window or qualifier filtering. RETRACTED terminal records contain only id and state. A retraction is an explicit provider report; there is no inferred cancellation or signed correction.

## AGG-007. Observation usability

Collapse byte-identical observations first. Missing observation yields OBSERVATION_MISSING; one UNAVAILABLE yields OBSERVATION_UNAVAILABLE; one INCOMPLETE yields OBSERVATION_INCOMPLETE. More than one distinct report yields OBSERVATION_CONFLICT. This bounded interface accepts one complete returned query bundle, not independently merged partial responses. A host that has several source responses must establish one complete attributable bundle under its declared provider contract; it may not fabricate completeness. Changing evidence identifiers does not authorize choosing between competing bundles.

NONE freshness accepts any otherwise usable nonfuture record. MAX_AGE accepts when evaluation minus as_of is at most the declared exact seconds; the duration obeys the precision grid. EXACT_REVISION requires exact revision equality. Failed freshness gives OBSERVATION_STALE. Event-snapshot coverage must contain the required interval, including each required inclusive endpoint; failed coverage gives OBSERVATION_INCOMPLETE. STATISTIC coverage must equal the required interval exactly because a wider statistic cannot be trimmed without history. A wrong statistic interval is INPUT_INVALID, not a stale fact.

One event snapshot contains the terminal state for each supplied event ID at its revision. Collapse exact duplicate events; two different records for one ID yield OBSERVATION_CONFLICT without choosing ACTIVE, RETRACTED, latest time or array order. Different supplied snapshots at later revisions may legitimately revise or retract an event; the pure evaluator has no hidden memory that overrides the selected current bundle. Within one snapshot select only ACTIVE events in the required interval, satisfying the declared source qualifier and matching a proposal partition's key. Zero selected events gives the reducer identity. Complete absence is distinct from unavailable history.

Revision identifiers are opaque equality tokens. There is no lexical, numerical or temporal revision ordering, and EXACT_REVISION may name any exact selected token. A complete snapshot may omit an inactive event or include its RETRACTED terminal state; both contribute zero. Authentic completeness, disclosed corrections and nonrollback selection are host premises, not deductions from revision spelling. Event order is immaterial after exact duplicate collapse. Statistics sort by canonical key bytes and have unique keys. Types, mappings, step identifier lists, operation rows, named fields, predicate MEMBER sets and pending rows must arrive in their specified sorted order; violations are admission errors. Observation arrays and snapshot event arrays may arrive in any order, subject to their defined duplicate/conflict handling.

A statistic bundle contains exactly one entry for every query key and no extra or duplicate key. COUNT requires a natural integer SCALAR; SUM a canonical nonnegative SCALAR of the definition's fixed unit; CARDINALITY a SET of the exact element type. No field may present a CARDINALITY count as a substitute for its set. A statistic asserts the accumulator for the exact bound query; provider truth and its event provenance are host responsibilities. Scalar statistics are supported by this evaluator but insufficient for identifying settled reservations; the initial shared-budget ledger therefore requires event history.

## AGG-008. Results and precedence

After a usable committed accumulator, add the partition's included pending contributions and all new contributions exactly once. SUM uses exact addition, COUNT adds one per contribution, CARDINALITY unions typed elements. Compare the resulting scalar or set size with the bound. A violated partition has reason BOUND_VIOLATED; a satisfied partition has no reasons. An indeterminate partition has null accumulator and result with its explicit observation or time reason. The result includes full typed SET accumulators, not just their size.

Root status is VIOLATED if any partition is violated, otherwise INDETERMINATE if any is indeterminate, otherwise SATISFIED. Root reasons are the UTF-8 sorted unique union of partition reasons. Partition reasons are sorted unique. Every partition remains present even if another determines root status. Result fields are exactly schema, specification_pin, definition_digest, status, partitions and reasons. The schema token is `seampoint.work-class/1.0.0-draft.2/aggregate-result`; pin and definition identity bind the admitted inputs.

Admission applies these phases: (1) closed input shape; (2) manifest pin and definition identity; (3) definition/reference/order invariants; (4) type/literal/operand integrity throughout definitions and dynamic inputs; (5) projection, source/query/time/coverage/statistic integrity; (6) finite limits; (7) time and observation usability; (8) comparison. Every refusal in this candidate uses an empty path. Phase 1 returns SCHEMA_INVALID. A pin mismatch returns VERSION_UNSUPPORTED; a definition-digest mismatch returns INPUT_INVALID, with the pin checked first. Phase 3 returns REFERENCE_INVALID. Phase 4 returns TYPE_INVALID. Phase 5 returns INPUT_INVALID. Phase 6 returns LIMIT_EXCEEDED. A later result never masks an earlier failing phase. Within a phase all errors have the same code and path. No implementation-specific diagnostics enter the result.

Bounds are the common limits: 64 types and 64 mappings, 256 operations, 1024 members per collection, 128 numeric coefficient digits, depth 64 and 4096 predicate nodes across the definition. Digit-limit checks belong in phase 6 after lexical/type/integrity checks. Intermediate exact totals may grow beyond 128 digits, up to the mathematically necessary result of admitted inputs; output growth is not a reason to silently wrap or round. Referenced collection limits apply before duplicate collapse except observations and event snapshots, whose exact repeated records collapse before their limits are measured.

The dynamic validation matrix is normative. Phase 4 TYPE_INVALID covers every supplied value's scalar payload, nominal type, contribution-field compatibility, key-tuple types, qualifier operand types and statistic accumulator type. This includes operation fields, pending rows, ACTIVE event fields, statistic entries and SET elements. A missing required field, duplicate dynamic field name, unsorted dynamic inventory, missing/extra statistic key, a repeated pending key, or a pending/new occurrence collision is phase 5 INPUT_INVALID. Unknown definition-level type references, duplicate definitions/mapping IDs and invalid static ordering are phase 3 REFERENCE_INVALID. COUNT scalar accumulators and COUNT/CARDINALITY results are natural integers; SUM scalar accumulators/results are canonical nonnegative decimals; CARDINALITY accumulators are SETs of the exact element type. Output shape schemas cannot express every relation to an input definition, so passing an output shape check alone does not establish this matrix. Implementations must produce the required semantic output, and frozen expectations compare its complete bytes.

## AGG-009. Readback and decisive evidence

Validation/readback admit the complete definition schema, identity/version, static references, literal/predicate semantics and limits. Definition schema is `seampoint.work-class/1.0.0-draft.2/aggregate-definition`. Readback uses common JSON-pointer leaf rendering over the whole definition, covering every operative field, including type, unit, window, source freshness and pending policy.

The worked sum has a complete committed accumulator of 800 USD, a bound LTE 1000 USD and a proposal of 150 USD, yielding 950 and SATISFIED. Two proposed 150 USD contributions in one partition yield 1100 and VIOLATED. With one earlier pending reservation of 150 USD, the remaining proposal also yields 1100. A CARDINALITY history containing B and C plus proposals A and B produces the set A,B,C and result 3. These judgments are arithmetic derivations; concrete fixture bytes and independently reviewed expectations must exist before they become conformance cases.

This successor restates its reducers, grouping, exact arithmetic, temporal windows and observation distinctions directly. The scalar-key-element restriction, one-complete-bundle adapter, derived contribution projection and explicit pending policy are successor profile and encoding decisions requiring compatibility review. They do not establish that every source aggregate can be translated without loss. Composite-valued key elements, business-day calendars, signed netting and currency conversion remain visible requirements for later profiles. A grouping key may still contain several scalar elements under AGG-003.
