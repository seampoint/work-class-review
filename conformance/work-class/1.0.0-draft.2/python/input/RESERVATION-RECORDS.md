# Reservation wire rules and reference limits

Status: `DRAFT_NOT_ADOPTED`, `APPARATUS_ONLY`. This normative companion and `reservation.schema.json` define the concrete finite records used by `RESERVATIONS.md`. The first reference profile is restricted to shared budgets: `RESERVE` with no `required_budgets` is `UNSUPPORTED_RELATION`. A lifecycle proposal with no declared shared budget uses the authority result directly and creates no reservation input. Its dispatch permit uses the proposal-capable step's required finite duration; this reservation contract supplies no additional horizon for that path.

## Configuration and administration

The registry digest is digest(reservation-registry,configuration). Configuration slot rows sort by anchor, with unique exposure_domain values. The principal and every identifier are explicit nonempty strings. The supplied host_evidence.registry_digest must match that exact configuration. Actual independent selection and protected persistence are host premises. A test adapter can receive these selected host facts as input; it cannot claim to have authenticated them.

An administrative subject is digest(reservation-administration-subject,{registry_digest,event_id,expected_revision,kind,clock,payload}). It includes the complete payload and excludes administration, preventing circular act subjects. A basis is a complete host-selected HUMAN designation for this registry, principal, administration role, actor and allowed REGISTER/RELEASE operation. Its provider/source equal the independently selected configuration. Its observed at equals the event clock, revoked is false, and its validity contains that instant. The basis is an explicit host assertion of organizational designation and current withdrawal status, not a business grant inferred from a credential. Authentication and truth of that assertion are host obligations.

The act's basis id, actor, role and principal match the complete selected basis; its kind matches the event; its subject matches the full administrative subject; occurred_at equals the event clock; disposition is ACCEPT. Its attributed return contains exactly its canonical bytes, digest(reservation-administration-act,act), same actor, administration provider/source and returned_at equal to the event clock. The return digest is digest(reservation-administration-return,returned). Missing complete basis or return authentication is EVIDENCE_UNAVAILABLE; a mismatched binding is DEPENDENCY_MISMATCH; well-formed expired, revoked or non-ACCEPT administration is ADMINISTRATION_NOT_ESTABLISHED. `REGISTER` and a `RELEASE` that would newly change an `OPEN` or `UNKNOWN` reservation to `RELEASED` carry this selected basis and return. A `RELEASE` that only retains a duplicate or contradictory no-effect fact against `SETTLED`, `RELEASED`, or `DISPUTED` carries null administration because it grants no release. Other events also carry null administration.

Authenticated-record tuples sort by canonical UTF-8 bytes and are unique. They contain exactly one row for each supplied payload history, native outcome and administrative return, using kinds HISTORY, NATIVE_OUTCOME and ADMIN_RETURN. Their digest kinds are budget-history, reservation-native-outcome and reservation-administration-return. The provider/source fields equal the full corresponding body. Extra or mismatched tuples are DEPENDENCY_MISMATCH, missing tuples EVIDENCE_UNAVAILABLE. The host selects these facts independently. Administrative basis authenticity is part of that separate selection, avoiding a recursive self-authentication record.

## Definitions and projections

A registered authorization's authority_definition must pass the complete AUTHORITY static definition admission. A static BINDING_MISMATCH is preserved as that reservation admission code, including an invalid gate floor or missing operative enforcement mechanism; it cannot become a malformed adapter response. Its class, class digest, envelope digest, principal and step match those full records, the budget definition and one permitted contributor class. Its envelope requires this budget anchor. Each projection has a unique budget_field and native_field, sorts by budget_field, and resolves to the declared native step field and budget type. The complete scalar declaration kind, unit and nonnegative flag must match, although the nominal identifiers may differ. Projection copies only the scalar value and explicitly changes type_ref to its declared budget_type. It never converts units, rounds a number or derives meaning from a field name.

For an occurrence, project its complete native fields through that authorization and apply every aggregate contribution mapping whose step_ids contains the native step. Validate every referenced grouping, qualifier and contribution field even when a qualifier is false. Each selected mapping produces one retained contribution {anchor,mapping,occurrence,key,value}. Its occurrence is the global occurrence-key digest. Contributions sort by canonical [anchor,mapping,occurrence,key] and are unique. Different mappings may affect different keys. At least one must be selected for every required anchor. All anchors, mappings, values and keys are retained, so renewal cannot silently change an already reserved contribution.

For this reconciliation profile, the aggregate committed_source qualifier is exactly BOOLEAN true. Its contribution kind matches the reducer, and its key field names are distinct from one another and from its numerical/element contribution field. These explicit normalized history fields receive already projected committed contributions. COUNT has no contribution field and contributes 1. Each terminal contribution's journal event id is digest(reservation-committed-event,{budget_digest,effect_id,mapping}). Its ACTIVE fields are exactly the committed_source's key fields with the contribution key values, plus its contribution field/value for SUM or CARDINALITY, sorted by field name. Its occurred_at is the native effect's declared time. That prescribed record ensures multiple mapping contributions settle once each without conflating their keys. Earlier unrelated history may use any unique event id.

The reference profile does not accept an arbitrary historical qualifier that could exclude a known native effect after settlement. More general history-source transformations require a later explicit contract. This is a supported-profile restriction, not evidence that those source semantics are unneeded.

## Complete history and native records

History arrays sort by budget_digest, are unique and contain exactly the affected budget set. REGISTER supplies one AVAILABLE complete initial history. RESERVE and RENEW supply all required anchors; SETTLE supplies all anchors of the referenced reservation. If an effect names an unknown reservation, its histories must identify at least one registered budget. That case is retained as disputed exposure on every supplied anchor, not admitted as a known reservation. All native/history providers and sources match their budget policy declarations. At RESERVE and RENEW, every affected policy must also agree on its settlement provider/source pair and its no-effect provider/source pair. A disagreement is `UNSUPPORTED_RELATION` before evaluation and leaves the complete registry unchanged.

An AVAILABLE history's journal is ordered by exact natural sequence 1 through revision with no gaps. The prior complete journal is an exact prefix. All event records retain AGG's scalar, date and field admission. Events cannot claim a future occurred_at relative to history.as_of, and as_of cannot exceed the current event clock. History freshness uses the aggregate committed_source declaration at the current clock. Exact-revision freshness must equal the supplied natural revision spelling. Non-AVAILABLE histories carry null revision/journal/as_of and complete:false. They cannot replace a retained complete history with an empty collection.

A native record always includes its complete attributed native request, nullable observed request, actual scalar fields and collections, completion-mismatch flag, nullable mismatch reason, reservation reference and evidence reference. EFFECT requires nonnull effect_id and occurred_at and `rules_out_past_and_future_effects:false`. Its observed request is the complete operation-field projection when that projection is possible. The reservation transition cannot see the completion bindings that map evidence field names to request field names, so it does not compare a nonnull observed request with the actual fields; it relies on the lifecycle's embedded record, and a host that submits a native record directly supplies an observed request that is that projection. A missing or unprojectable actual field permits null only with `completion_mismatch:true`. UNKNOWN requires null effect_id, occurred_at and observed request, an empty actual-field and collection inventory, and the no-effect flag false. NO_EFFECT requires null effect_id, occurred_at and observed request, an empty actual-field and collection inventory, and the no-effect flag true; it is usable only for RELEASE. UNKNOWN and NO_EFFECT permit either completion-mismatch value. `completion_mismatch:false` requires `mismatch_reason:null` and is required for an ordinary UNKNOWN retention or an affirmative release. `completion_mismatch:true` requires exactly `NATIVE_REQUEST_MISMATCH` or `UNEXPECTED_EFFECT`. The first identifies changed native arguments or another dispatch-disqualifying fact. The second identifies an otherwise attributable record that the wider lifecycle classifies as unexpected or conflicting, including a no-effect assertion whose attempt set is not final and safe. Either mismatch is retained as disputed exposure and can never release capacity or establish a normal outcome. These relationships are semantic admission requirements. A record of the wrong outcome kind or a mismatch flag and reason that disagree is INPUT_INVALID. The body is never classified by its English evidence_ref.

The attributed native request is the exact projection of an authority proposal's work_class, instance, occurrence, step, operation, interface and fields. Equality compares complete canonical records. The observed request, when nonnull, uses the same identity fields and the actual operation fields supplied by the observation. A matching settlement requires `completion_mismatch:false`, equality of attributed, observed and reserved requests, and all prescribed committed event records in every supplied current journal. Missing journal corroboration retains EFFECT_DISPUTED rather than claiming settlement. `completion_mismatch:true` on any native outcome, a null observed request for EFFECT, different native fields, a second distinct effect id, an unknown reservation or a journal disagreement likewise retains EFFECT_DISPUTED. Such facts block the sorted union of the original reserved partitions and every actual partition that can be projected from complete well-typed observed fields under the exact retained class authorization. A different class, step or interface, unknown nominal type, missing or extra native field, unprojectable qualifier, null observed request, or UNKNOWN or NO_EFFECT mismatch without actual fields blocks the affected anchor through a null key. That null-key entry is the anchor's only entry for the fact; it already covers the original reserved partition. The immutable reservation policy expressly selects `BLOCK_AFFECTED_PARTITIONS` and, for an unprojectable fact, `BLOCK_ANCHOR`. The implementation supplies neither choice by default. Each retained disputed effect carries `blocked_partitions` entries `{anchor,key}`, with null key only for that explicit unprojectable case. A new contribution is blocked only when its anchor and exact key match one retained entry or that anchor has a null-key entry. An unrelated known partition remains admissible.

A duplicate native record id with identical complete bytes does not create another effect or release. It returns the established effect disposition in a new receipt when wrapped in a new event id. A changed body under the same native record id is INPUT_INVALID, leaving the original retained evidence unchanged; the host retains the raw conflicting record for resubmission under its own distinct evidence identity. A different evidence record with the same complete fact after omitting only its evidence identity and reference is also a duplicate. For one `effect_id`, an equal complete fact is duplicate; a changed conclusive fact is conflicting and disputed but adds no second committed contribution for that effect identity. A second distinct effect ID for one occurrence is unexpected additional exposure and disputed, even when its request repeats the original fields.

For a known reservation, reconciliation uses this complete prior-state table after lifecycle classification and duplicate detection:

| Prior reservation state and new native fact | Receipt decision | Next reservation state and exposure |
|---|---|---|
| Any state; `UNKNOWN` or `NO_EFFECT` with `completion_mismatch:true` | `EFFECT_DISPUTED` | become or remain `DISPUTED`; retain or restore the unresolved pending charge, retain the evidence, block the affected anchor, and never release capacity |
| `OPEN` or `UNKNOWN`; matching `EFFECT` | `SETTLED` | `SETTLED`; replace pending exposure with the exact committed contribution once |
| `OPEN` or `UNKNOWN`; attributable `EFFECT` that is unexpected or conflicting | `EFFECT_DISPUTED` | `DISPUTED`; retain pending exposure and every projectable or anchor-level dispute block |
| `OPEN` or `UNKNOWN`; `UNKNOWN` | `UNKNOWN` | `UNKNOWN`; retain pending exposure once |
| `OPEN` or `UNKNOWN`; authorized `NO_EFFECT` with no conflicting terminal effect | `RELEASED` | `RELEASED`; remove pending exposure once |
| `SETTLED`; duplicate matching `EFFECT` | `SETTLED` | remain `SETTLED`; add no committed or pending exposure |
| `RELEASED`; duplicate `NO_EFFECT` | `RELEASED` | remain `RELEASED`; add no exposure |
| `SETTLED` or `RELEASED`; later `UNKNOWN` | `UNKNOWN` | retain the native evidence and prior terminal state; change no exposure |
| `SETTLED`; contradictory `NO_EFFECT` | `EFFECT_DISPUTED` | become `DISPUTED`; retain the committed history, restore the unresolved pending charge and block affected partitions |
| `RELEASED`; later `EFFECT` | `EFFECT_DISPUTED` | become `DISPUTED`; restore the unresolved pending charge, retain the actual effect and block affected partitions |
| `SETTLED`; nonduplicate `EFFECT`, or any conclusive conflict | `EFFECT_DISPUTED` | become `DISPUTED`; retain all conclusions, restore the unresolved pending charge and block affected partitions |
| `DISPUTED`; any new attributable fact | `EFFECT_DISPUTED` | remain `DISPUTED`; retain the fact and existing conservative exposure; perform no automatic resolution |

A record with `completion_mismatch:false` whose attributed request differs from the reserved request is retained as `EFFECT_DISPUTED` under the ordered reason list, for SETTLE and RELEASE alike, and the reservation becomes or remains `DISPUTED`. The `UNKNOWN` and `NO_EFFECT` rows above apply only to records whose attributed request equals the reserved request.

Every admitted row advances the registry revision and retains the exact event and host evidence. `RELEASE` carries `NO_EFFECT`; it carries administration only when an `OPEN` or `UNKNOWN` reservation with `completion_mismatch:false` would newly become `RELEASED`. A mismatched NO_EFFECT carries null administration because it cannot authorize release. `SETTLE` carries `EFFECT` or `UNKNOWN`. A duplicate returns the established disposition named above and does not repeat an effect record or charge. Duplicate recognition depends on the native fact, not on the supplied history; a duplicate stores none of its supplied history and changes no registry fact beyond the receipt and revision. A later unknown receipt does not mean the terminal reservation became unknown. No row discards evidence or infers that a contradiction resolved itself.

When a history newly admitted with a non-duplicate event revises or retracts a prescribed event for a SETTLED reservation, mark it DISPUTED, restore its unresolved pending charge and retain its matched_effect and original native records. For reserve/renew, stale or unavailable history does not update that budget's journal. A refusal receipt may retain newly supplied evidence in its complete event. SETTLE retains native evidence even when its supplied history is unavailable or incomplete; its result is disputed and blocks the affected budget. No ambiguity about observation usability can turn unexpected real-effect evidence into empty state.

## Core transitions and state reconstruction

Core budgets sort by definition.anchor; reservations and effects sort by id. A receipt stores exactly the fields in the closed schema. State.receipts is a contiguous revision-ordered list of {event,host_evidence,receipt}, retaining complete admitted event and selected host facts. Revision 0 has no budgets, reservations, effects or receipts and last_clock:null. Every admitted event increments revision by one, including WITHHELD. Its receipt.prior_state_digest equals the preceding complete state digest; next_core_digest hashes the resulting core. The current revision equals the number of receipts. Current last_clock is the most recent admitted AVAILABLE event clock; an unavailable clock does not change it.

State admission replays the retained admitted events from the empty core with the same immutable configuration and candidate. A supplied state or retained record bound to a different specification pin fails state admission with STATE_INVALID. It checks each prior state digest, event digest, result receipt and final core exactly. Historical selected facts are replayed as records of what was supplied then; the replay does not turn them into current authority. This construction defines a complete reference validation algorithm and makes unreachable or altered state detectable without hidden process memory. A conforming implementation may validate the same invariants more efficiently if it admits exactly the same states.

The event replay identity includes complete event bytes. It excludes new host_evidence so an exact old event remains an evidence lookup, not a new grant. After state and selected registry binding admission, exact replay returns the stored receipt with current state and replay:true; it neither revalidates expired authority nor grants another dispatch. A fresh event must supply its own exact complete current host facts. An altered old event fails REPLAY_CONFLICT. Hosts must not mistake a replay response for a new RESERVED permission.

Within each admission phase, the fixed code order is SCHEMA_INVALID, ARTIFACT_ENCODING_INVALID, ARTIFACT_NONCANONICAL for phase 1; DEPENDENCY_MISMATCH, STATE_INVALID for phase 2; REPLAY_CONFLICT for phase 3; REVISION_CONFLICT, CLOCK_INVALID for phase 4; then DEPENDENCY_MISMATCH, EVIDENCE_UNAVAILABLE, UNSUPPORTED_RELATION, REFERENCE_INVALID, BINDING_MISMATCH, TYPE_INVALID, INPUT_INVALID, LIMIT_EXCEEDED, DEFINITION_CONFLICT, OCCURRENCE_CONFLICT, RESERVATION_NOT_FOUND, ADMINISTRATION_NOT_ESTABLISHED for phase 5. Missing reservation references in RENEW/RELEASE are admission failures. SETTLE has the explicit foreign-effect retention rule above. No implementation exception becomes one of these codes.

Policy decisions use sorted unique reason identifiers. AUTHORITY_WITHHELD retains the complete authority refusal; HISTORY_UNAVAILABLE, HISTORY_INCOMPLETE, HISTORY_CONFLICT and HISTORY_STALE identify unusable full history; BOUND_VIOLATED retains the actual violated aggregate result; EXPOSURE_DISPUTED names a blocked anchor; CLOCK_UNAVAILABLE is the sole clock-unavailable reserve/renew reason after earlier integrity checks. Successful decisions have no reasons. Native retained decisions use MATCHED_EFFECT, UNKNOWN_OUTCOME, AFFIRMATIVE_NO_EFFECT, NATIVE_REQUEST_MISMATCH, UNEXPECTED_EFFECT, HISTORY_UNCORROBORATED, UNKNOWN_RESERVATION or LATE_EFFECT_AFTER_RELEASE as the effect reason. UNKNOWN_RESERVATION, and then LATE_EFFECT_AFTER_RELEASE, take precedence over every other reason, including the native record's mismatch reason and the ordered list for a record with `completion_mismatch:false`. LATE_EFFECT_AFTER_RELEASE applies only to an EFFECT record against a RELEASED reservation; a completion-mismatched UNKNOWN copies its `mismatch_reason`. Otherwise a completion-mismatched record copies its required `mismatch_reason` exactly. Otherwise a record with `completion_mismatch:false` takes the first applicable reason in this order, whatever the prior reservation status: `UNEXPECTED_EFFECT` when it names a second distinct effect identifier for the occurrence, a changed conclusive fact under a retained effect identifier, an attributed or observed request that differs from the reserved request, or, for a no-effect record, a contradiction of the reservation's matched effect; `HISTORY_UNCORROBORATED` when an effect lacks complete journal corroboration; otherwise `MATCHED_EFFECT`, `UNKNOWN_OUTCOME` or `AFFIRMATIVE_NO_EFFECT` for its outcome. Against an already `DISPUTED` reservation its receipt decision is `EFFECT_DISPUTED` and the reservation remains `DISPUTED`. Receipt reasons copy the retained native reason for EFFECT_DISPUTED and are empty for SETTLED, UNKNOWN or RELEASED.

A refused RENEW does not change its reservation, permit or evidence; the refusal receipt records the failed new request. A successful RENEW replaces current authority and authority_result and permit_until, preserving contributions, creation time and status. UNKNOWN remains UNKNOWN until terminal evidence. OPEN/UNKNOWN/DISPUTED reservations supply pending exposure regardless of time. SETTLED/RELEASED do not. An already DISPUTED reservation cannot be renewed or released; WITHHELD with EXPOSURE_DISPUTED retains it. Permit expiry is exact now plus the minimum positive permit_seconds across affected budgets, and date overflow is LIMIT_EXCEEDED. A runtime must not dispatch on WITHHELD, replay:true, expired permit or a prior receipt superseded by renewal.

A top-level input that fails its closed structural schema returns exactly `{status:"REFUSED",code:"SCHEMA_INVALID",path:""}`. No unadmitted state is echoed. All subsequent stateful admission refusals preserve and return the exact supplied state and digest; the host never commits a refusal as replacement state. This distinction also applies when invalid embedded bytes are found after the outer input has passed structural admission.

Receipt budgets contains the aggregate judgments actually evaluated by RESERVE or RENEW, ordered by anchor. REGISTER, SETTLE and RELEASE have budgets:[] and authority_result:null; they do not perform a new proposal aggregate evaluation. A withheld authority result also leaves budgets empty. Native settlement and release retain their evidence and state consequences without fabricating a fresh SATISFIED aggregate judgment.

An unknown reservation has no retained original exact work-class and envelope binding. Its native request contains a stable class identifier, not those complete versioned subjects. Therefore the foreign-effect rule blocks each affected anchor with key:null; it must not guess a projection from whichever current class authorization has a matching name. For known reservations, blocked_partitions is the canonical sorted unique union of original and actually projectable keys when the fact is projectable, so the same key is never repeated, and the anchor's single null-key entry when it is not.

A normalized aggregate journal event supplies a contribution and event time. Equality of its amount and grouping fields with an earlier reservation does not identify the invocation that caused it. The host must submit a complete native outcome record through SETTLE when later evidence attributes an effect to a RELEASED reservation. General newly observed journal contributions are retained and counted, but the consumer does not infer a contradictory native effect from matching business fields or attempt to invert an opaque event digest. This attribution boundary does not allow the host to discard known late native evidence.
