# Independent human decisions and retained commitment evidence

Status: `DRAFT_NOT_ADOPTED`, `APPARATUS_ONLY`. This normative companion defines explicit bounded alternatives to inherited single-principal gate, dispatch and correction carriers. Omitted new members retain inherited bytes and rules. Every supplied independent decision remains evidence; ordinary execution authority, reservations, provider commitment and completion are separate checks.

## AUTH-008. Independent HUMAN evidence, exact bindings and result

`decision_requirements` rows are exactly `{id,step,principal,role,work_class_digest,envelope_digest,record_requirement_id,identity_field,validity_fields,context_bindings,distinct_from}`. `context_bindings` rows are `{field,value}` with value either `{kind:"PROPOSAL_FIELD",field}` or `{kind:"LITERAL",value:<typed value>}`. The bounded assessment profile additionally admits the four computed context members defined in [ASSESSMENTS.md](ASSESSMENTS.md), with its exact binding and nominal-bridge requirements. Rows sort uniquely by field. `distinct_from` rows are `{kind:"EXECUTOR"}` or `{kind:"DECISION",requirement_id}` and sort uniquely by complete canonical bytes; self references fail REFERENCE_INVALID.

Declarations sort uniquely by id, at most 16. Each names an existing operation step and an in-step AVAILABLE AUTHORITY record requirement. Every supplied selected leaf has the exact declared work-class/envelope digests, principal and HUMAN gate role. `context_bindings` exhaustively covers the exact leaf proposal fields. Each PROPOSAL_FIELD resolves in the outer step; each LITERAL is fully typed. Each explicit nominal bridge resolves complete declarations in both classes, requires identical id/kind/unit/nonnegative members, validates each scalar in its own class and compares exact typed values. Outer scalar walkers never validate nested leaf values under outer types. The leaf clock retains its own declared source, but availability and instant equal the outer clock. Its proposal executor's actor/role/principal/occupancy equal the unique selected HUMAN INSTANCE_DECISION signer. The wrapper digest equals that act's digest, and every normal act/return/root/capacity check applies except the historical signer's current executor-occupancy test.

identity_field selects one STRING/IDENTITY leaf proposal field included in context_bindings. Its value is exactly the canonical JSON string of `{provider,source,record_type,provider_record_id}`, with provider/source/record_type from record_requirement_id and provider_record_id the selected decision act's immutable id. The requirement's nonnull record_id equals that id. ASSESS-004 defines the sole assessment-linked exception: a null record_id with locally derived REVIEW_IDENTITY and mandatory exact returned-record/act equality. This binds the native identity and corrected identity to the independently authenticated issuance, rather than a caller-renamed link.

`decision_bases` rows are exactly `{requirement_id,evidence}`. Evidence is `{schema:"seampoint.work-class/1.0.0-draft.3/human-decision-evidence",authority_input,decision_act_digest}`. The closed leaf schema requires work_class.authority_profile EVIDENCE_ONLY and excludes decision_bases, assessment_bases, envelope.decision_requirements and envelope.assessment_requirements. The ordinary input schema does not admit that marker. Static leaf definitions may validate/read back without producing authority readiness. Its single work-class step has quantity_mode NONE, empty exclusive_keys and required_credentials, no completion and no dispatch_gate. Input credentials and envelope numerical limits are empty. The leaf gate is DECIDE and cannot refer to an independent decision requirement.

A successful leaf result copies the standard result's complete members, except schema is `seampoint.work-class/1.0.0-draft.3/human-decision-result`, status is EVIDENCE_VALID, and required `decision_act_digest` identifies its unique admitted decision. Required `effective_until` is the derived finite exclusive end of its continuous current reliance, bounded by its own decision end. It omits EXECUTOR_OCCUPANCY both as a current test and as an asserted successful check. It has no decision_results. Its result digest uses the existing authority-result domain; schema and complete bytes distinguish it.

Outer `decision_results`, when decision_bases was supplied, is exactly the requirement-id-sorted collection `{requirement_id,result,result_digest}`, with result the complete human-decision result or complete ordinary authority refusal. Every result_digest uses authority-result. No property is inserted for omitted decision_bases. An explicit [] produces explicit decision_results:[] and enters the evidence digest.

New check purpose HUMAN_DECISION is `{purpose:"HUMAN_DECISION",subject_digest:<selected leaf decision act digest>,requirement_ref:<requirement id>,at:<outer accepted now>}`. Current leaf failure contributes DECISION_NOT_EFFECTIVE to this parent check, retaining the underlying complete leaf result. Explicit actor separation failure contributes DECISION_SEPARATION to a SEPARATION check with the same subject/ref/time. Multiple failures produce both rows and reasons. CLOCK_UNAVAILABLE retains the inherited sole reason and empty failed_checks after directly checkable phases 1..4 and the assessment profile's post-act chronology binding; available leaf clocks cannot override an unavailable outer clock. Normal success emits HUMAN_DECISION and every explicitly required SEPARATION row.

Admission runs each phase across outer input and supplied selected leaves before advancing to the next phase, choosing the inherited within-phase code order across all failures. Phase 1 admits directly resolvable known scalar/type incompatibilities, including complete nominal bridges. Phase 2 admits declarations, exact base inventory/pins, nonrecursive profile and unresolved references. Phase 3 admits exact selected principal/role/clock, subject/context and executor coordinates. Phase 4 admits leaf acts/returns. Phase 5 joins complete ordinary and leaf query inventory before current policy failures. This prevents a parent current failure from hiding an earlier leaf admission fault. When several requirements fail at phase 5, retain every selected leaf's complete result in decision_results. Earlier admission refusals need not add decision_results. Bases sort uniquely by requirement_id and contain exactly the requirements selected by the proposed step: missing is EVIDENCE_UNAVAILABLE; unrequested is DEPENDENCY_MISMATCH; duplicate/sort errors are INPUT_INVALID. Unknown named declarations are REFERENCE_INVALID; known incompatible full nominal bridges are phase-1 TYPE_INVALID; exact context/digest/identity application mismatch is BINDING_MISMATCH under the inherited phase order.

Dispatch refresh may change only outer/leaf clocks, observations and evaluation_point. Every other complete byte and optional-member presence is immutable. Include supplied decision_bases in the authority-evidence preimage if and only if present. Recompute retained historical results at their retained clocks on restart; later revocation cannot rewrite historical authority or erase an effect. Source/constructor correspondence must establish the one-way dependency order: dossier first, independent leaf definitions/subjects/acts next, execution definition/request last. Neither leaf context contains the other decision identity/digest, finished outer proposal/definition/envelope digest or future native/correction event. No excluded policy field or opaque current receipt replaces a complete body.

DECISION_ACT selector is `{kind:"DECISION_ACT",requirement_id,member,type_ref}` with member digest/id/actor/role/principal/occurred_at. Text members require STRING/IDENTITY and time INSTANT. DECISION_FIELD is `{kind:"DECISION_FIELD",requirement_id,field}`. Its full nominal declaration bridges to the parent exactly. Both select phase-4-admitted evidence, never an unvalidated caller digest. A parent AVAILABLE AUTHORITY record must carry EQUALS relations between its OBSERVATION_ID and DECISION_ACT.id; between its own OBSERVATION_FIELD and each other DECISION_ACT member; and between its own OBSERVATION_FIELD and every declared DECISION_FIELD. Either equality direction is admitted. A coverage check matches exact selectors, never relation id spelling. The complete query/observation remains subject to normal independent admission.

Each decision requirement additionally has required validity_fields `{not_before_field,not_after_field}` selecting distinct INSTANT fields in its leaf proposal. Their values equal the leaf envelope temporal_validity.valid_from and nonnull valid_until. Both endpoint fields are included in exhaustive context_bindings and record relations. A source gate includes each decision record and a validity row whose own source fields are linked by exact EQUALS relations to those two leaf fields.

DECISION_BASIS is `{kind:"DECISION_BASIS",requirement_id,type_ref}`. It returns the typed digest of `digest("human-decision-reliance-subjects",{root_digest,envelope_digest,capacities:[{id,capacity_digest}]})`, with capacities sorted by id and including every complete supplied capacity. Its type is STRING/IDENTITY. The source explicitly guards an AVAILABLE authority-scope record for each party containing this digest and a no-applicable-revocation conclusion; all root/capacity/envelope revocation and remit writers join the selected coordinator.

A successful leaf effective_until is the minimum of its envelope valid_until, the root valid_until when prior_acts_survive_expiry is false, every selected return-channel valid_until when prior_returns_survive_expiry is false, and every selected capacity's continuous reliance end. For CURRENT_ONLY use capacity.validity.valid_until. For SURVIVE_EXPIRY use the upper end of the connected union of capacity.validity and reliance.validity that contains now; disjoint future intervals cannot extend the current interval. Null ends contribute no upper bound. Past signer occupancy end supplies no current cutoff.

Each complete decision-bearing authority input is at most 1048576 canonical bytes and each leaf input at most 262144 canonical bytes. Exceeding these bounds is phase-2 LIMIT_EXCEEDED. Limits apply before current-policy evaluation, independently of per-tree finite bounds.

## AUTH-009. An independent decision selected by the execution gate

An optional gate `decision_requirement` names one in-step declared independent decision and is permitted only for DECIDE. It selects that leaf's exact admitted decision as the outer gate act; the ordinary selected act set then contains the GRANT and its organizational attestation, with no additional ordinary INSTANCE_DECISION. Ordinary inputs without this property retain current semantics.

Require the selected leaf's principal/role to match outer gate principal/role and require the applicable criterion ids to match. Translate each selected leaf criterion's FIELD operands through its exhaustive context bindings to the corresponding outer FIELD or typed LITERAL. Literal-only types also require the same complete nominal bridge. The translated predicate must equal the outer criterion predicate exactly; no equivalence solver or English interpretation is used. Parent gate criteria are checked on its exact proposal at the admitted leaf decision occurrence. Retain the leaf's attestation, root and full current reliance. No historical-signer exception applies to the actual executor. Leaf gates cannot select this property, so the chain is one level only. Keep ordinary act_digests and permit authority_act_bases unchanged. Parent gate criteria and prior-actor separation resolve the selected leaf from complete verified decision results/bases. Recovery controller independence excludes every admitted leaf actor in addition to the executor and ordinary actors.

When a withheld prior-actor separation has nonempty authority_result.decision_results, its SEPARATION detail additionally retains authority_basis, the complete authority input used for that proposal. Omitted or empty decision_results retain the inherited detail without this member, except that ASSESS-006 additionally requires the complete carrier whenever the original proposal supplied assessment_bases, including []. Retained validation re-evaluates that input at its retained clock and requires the complete result and digest to match authority_result. It binds the authority projection, envelope, proposed operation, current occurrence and accepted historical clock to the definition and receipt. It resolves ordinary selected acts and, when the gate names decision_requirement, exactly that admitted selected decision. The current actor basis must match the declared separation act kind and one of those exact selected bases; another successful independent result cannot substitute. Missing authority_basis with nonempty decision_results, authority_basis with omitted or empty decision_results and no supplied assessment_bases member, or an inconsistent carrier is invalid retained state. This exception preserves assessment-member presence; it adds no human result or assessment check to an ordinary empty profile.

An already retained LATE_OR_PROHIBITED_DISPATCH row with an absent, unknown or mismatched authorization claim has no authorized historical revision basis. ## LIFE-020B. Corrections with fresh independent business decisions

Legacy policy and record/result carriers remain unchanged when the new policy kind is absent. New policy is the old policy's complete members plus `kind:"INDEPENDENT_HUMAN_DECISIONS"`, `business_decision_requirements`, `business_context_bindings` and `fresh_result_fields`. business_decision_requirements is 1..16 exact authority decision declarations. business_context_bindings is 1..64 unique rows sorted by proposal_field, each `{proposal_field,value}`. value is `{kind:"CORRECTED_FIELD",field}` or `{kind:"LITERAL",value:<typed value>}`. fresh_result_fields is a nonempty sorted unique inventory of completion fields that must each differ from the corresponding original requested value and original retained native value when a business correction is made. Every fresh_result_field must be an existing request-bound completion field. The selected source names the required fresh dossier fields.

New correction record copies legacy record minus new_approval_basis, plus required `decision_policy:"INDEPENDENT_HUMAN_DECISIONS"`. New result copies legacy result minus new_approval_result/new_approval_result_digest, plus the same decision_policy marker. Full fresh decision results remain inside correction_authority_result.decision_results, without a redundant second collection.

Business change requires correction_authority_input.envelope.decision_requirements to equal the policy's complete selected declarations and decision_bases to admit exactly those decisions. A nonbusiness correction admits no declarations or bases beyond omitted/explicit-empty. Full corrected business context is obtained from the explicit business_context_bindings, validated in the correction class with exact full nominal bridges from the original completion class, and must equal the proposal. It exhaustively covers every correction proposal field except the five exact correction-control fields, and therefore every PROPOSAL_FIELD selector used by the business decisions. The correction-control fields bind original identity/digest/revision and exact changes/result digests; result_digest_field is now always bound in this branch.

For each fresh decision compare immutable act digest and act identity against the original retained decision basis. Resolve each decision's identity_field through its PROPOSAL_FIELD context binding and that correction proposal field's CORRECTED_FIELD business_context_binding. Require that exact binding shape and one request-bound corrected identity field. Its value equals the canonical provider-issuance identity admitted under AUTH-008. The current declared record relation binds its new issue id to that corrected identity field. That corrected field must differ from both the original request and the attributable original event value. Record revision/context must be independently present and match its leaf context. The record decision_policy equals the explicitly selected policy kind; no legacy carrier substitutes for this branch. Match each fresh decision to the original retained requirement id and principal/role, and compare its act id/digest against that complete original basis. Require both fresh decisions when any business field changes. No old decision is renamed into freshness. Fresh selected act ids and digests must be disjoint from every original retained independent decision, not only the decision with the same requirement id; fresh selected act ids are unique among all fresh decisions. Every business-decision PROPOSAL_FIELD context selector must name a business_context_bindings proposal field and must not name any correction-control field. Authorization_revision_bindings fields cannot occur in changes. No original authorization carrier is added solely for corrections, and EVIDENCE_VALID establishes neither old completion nor a new dispatch opportunity.

Fresh correction decisions require new immutable issue ids, new act ids and new act digests. Revision inequality alone is insufficient. Exact opaque revisions are retained but never ordered. Each fresh correction decision uses a distinct immutable issue id.

## HOST-004. Prior history, writer coverage and protected evidence

A source-selected AVAILABLE complete prior-attempt-history record is keyed by batch/site/candidate request and excludes the candidate itself. It asserts no other unresolved/possibly in-flight attempt. Candidate registration precedes dispatch authorization. The authoritative scoped revision and coordinator cover all other attempt-registration/status/effect writers; the candidate's own intent progress changes neither selected prior-history conclusion nor its scoped revision. The provider checks complete prior-history/current-inventory prerequisites and both uniqueness domains atomically with update. This prevents a fresh disposition identity from evading unresolved predecessor history.

Each guarded root/capacity/envelope revocation, party-remit, agreement, dossier/evidence, decision/withdrawal, hold and prior-attempt writer must join the declared coordinator. A source documents the complete writer inventory. A provider atomically checks complete selected revisions/statuses, decision effectiveness, authorization expiry, current inventory expected revision, complete prior-attempt conclusion and both uniqueness domains with native update/event creation. A change before commit blocks; a change after commit preserves the historical event and creates separate work. Process-local tests establish only exercised conditional behavior, not real all-writer coverage or durable recovery.

Actor identities used for person separation are canonical host-selected human-subject identities across principals. The host resolves account aliases before admission and authenticates that mapping. Exact different strings alone do not prove distinct people. The consumer checks exact selected identities and declared separation.

Complete authority inputs/results and signer/source details belong to protected internal audit interfaces. Host/connector callers receive the declared closed status/digest response carriers; unauthenticated external access to protected results is not granted by this contract. Authentication, access control, retention and truthful provider/identity assertions remain explicit host responsibilities.

The executor must remain current at proposal and dispatch. A later executor session, occupancy or credential end is outside this source-vector commitment guarantee unless explicitly guarded by the selected source. Covered remit revocation remains a commitment check. Postcommit referral intent does not prove delivery, human action or containment. The bounded correction profile cannot repair the historical commit-revision field; a provider needs a separate authorized procedure for that fact before production reliance.
