# External source corrections

The explicit independent-decision, source-vector, dynamic completion and correction alternatives in [INDEPENDENT-HUMAN-DECISIONS.md](INDEPENDENT-HUMAN-DECISIONS.md) govern when selected. All inherited carrier inventories and behavior remain unchanged when those members are absent.

Normative draft 3 contract. Status: `DRAFT_NOT_ADOPTED`; claim ceiling: `APPARATUS_ONLY`. Corrections remain outside the original return-to-service lifecycle. This record validates exact correction authority and attributable source evidence; it neither edits provider history nor reopens original work.

## 2. Exact changes

changes is a nonempty raw-UTF-8-field-sorted unique array of at most 64 `{field,old_value,new_value}`. Each replacement or addition names a field in the original complete completion inventory; the explicit removal rule below permits undeclared original extras. old_value equals the exact original field value, or is null only when that declared field is absent. For a declared field, new_value is a nonnull valid value of its declared nominal type, differing from old_value. An undeclared extra original field may be removed only by a change whose old_value equals its exact retained value and new_value is null; no undeclared field may be added. Ambiguous duplicate original fields refuse BINDING_MISMATCH rather than choosing one value. Duplicate changes, wrong old values or no-op changes refuse BINDING_MISMATCH; malformed new declared scalar values refuse TYPE_INVALID. Provider metadata outside actual_fields cannot change through this carrier.

corrected_fields is the complete sorted named typed field inventory obtained by applying precisely those replacements, additions or removals to original_record.actual_fields. Its resulting field inventory equals the full source-declared completion inventory with valid nominal values. It need not equal the old request values when an explicitly approved business result changes. Compare its complete canonical bytes to this derived inventory. changes_digest is digest("source-correction-changes",the exact full changes array). result_digest is digest("source-correction-result",the exact complete corrected_fields). A caller hash alone cannot replace either body. For every provider_link_binding, the corrected link scalar equals the canonical JSON string of `{provider,source,record_type,provider_record_id}`, using the declared coordinates and the corrected record_id_field scalar. An unqualified link, wrong provider tuple or link to another approval refuses BINDING_MISMATCH. Changing approval therefore requires a corresponding link change and the independent new approval basis.

Changing a generated event identifier or timestamp remains a linked correction to the selected original event. It does not rename or delete that immutable provider record, make the corrected event appear to be the original, or rewrite the original occurrence. The provider/coordinator must retain the original and the separate linked correction event under its declared history policy.

The host independently authenticates and retains the selected custodian occupancy and return. A digest does not supply a missing identity record or signature.

The independently admitted envelope principal equals the original principal, executor_role equals the custodian role, and gate disposition is DECIDE. Otherwise it must be null. Its envelope principal equals the original principal; the unique positive GRANT has role correction_policy.issuer_role, an id different from the original approval provider_record_id and original selected grant id, and a signing instant no later than correction event_time. Its exact native authority proposal contains result_digest_field as a declared IDENTITY/STRING field whose value equals the full result_digest. Its admitted result is READY_FOR_RESERVATION, which proves the supplied approval basis only; it does not reserve, correct, dispatch or grant another return-to-service act.

Policy-selected business-result membership determines the new approval requirement exactly; a model summary does not choose it.

## 5. Result and refusal

A successful check-evidence result is exactly `{status:"EVIDENCE_VALID",profile:"LINEAR",role:"REVIEW_EVIDENCE",specification_pin,kind:"SOURCE_CORRECTION",definition_digest,original_record_identity,original_record_digest,correction_digest,correction_authority_result,correction_authority_result_digest,new_approval_result,new_approval_result_digest,changes_digest,result_digest}`. The result retains complete independently recomputed authority results; nullable new-approval members are null together when no new basis is required. This result creates no work/registry/terminal/referral change and invokes no provider. It records neither a corrected native event nor successful external correction delivery.

Pre-admission schema or candidate-selection failures use the existing generic `{status:"REFUSED",code,path:""}` result. After SOURCE_CORRECTION admission, refusals use exactly `{status:"EVIDENCE_INVALID",profile:"LINEAR",role:"REVIEW_EVIDENCE",specification_pin,code,path:""}`. Success and admitted refusal results include no state or registry members. Use the existing check-evidence refusal precedence: transport/canonical admission; candidate/profile/role selection; closed schema and known outer date admission; exact definition/permit/basis; original provider record and declaration references; changed-field/old-value/revision/result/custodian binding; independently admitted current correction authority; exact correction-decision and proposal-scope bindings; business-result/new-approval requirements and independent fresh approval; final provenance digest and result. Outer definition, original permit and retained original authority result digest disagreement is DEPENDENCY_MISMATCH. Original provider attribution/digest, revision, correction coordinates, change/inventory, typed proposal value, selected decision, fresh-approval identity/result and provenance disagreement is BINDING_MISMATCH. New declared values with an unknown or wrong nominal type or invalid nominal scalar are TYPE_INVALID. Missing required current authority evidence is EVIDENCE_UNAVAILABLE; wrong custodian declarations or return bindings are BINDING_MISMATCH before current authority evaluation; incorrect actor/role/scope within the current authority basis or withheld current authority yields EVIDENCE_UNAVAILABLE rather than a fabricated positive result. Full underlying refusal remains protected in the host's check-evidence audit input/result package.

No success or refusal edits the selected original record, seed claims, work state, old approval or terminal history. A later return-to-service instance independently presents a new request, work order, inspection and approval, obtains fresh authority and claims all five identifiers against complete mediated history. A correction never supplies an identifier release or original-instance replay.
