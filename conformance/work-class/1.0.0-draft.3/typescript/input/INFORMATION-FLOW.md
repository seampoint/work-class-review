# Information flow, retained provenance and first exposure

Status: `DRAFT_NOT_ADOPTED`, `APPARATUS_ONLY`. This development companion defines the frozen first-profile wire for the information-flow implementation package. It defines a finite host-owned registry for accumulated context restrictions and exact disclosure claims. Ordinary authority and content judgments remain separate requirements.

## FLOW-001. Immutable catalogue and host-selected contexts

Configuration is `{schema,specification_pin,id,principal,provider,source,protected_channel,clock_source,control_interface,access_operation,transfer_operation,response_operation,response_role,restrictions}`. Its digest is `digest("flow-configuration",configuration)`. Each restriction is `{id,scope,meaning,releasable,release_role}`. Identifiers and restrictions sort uniquely by UTF-8 id. Scope and meaning are immutable; release_role is nonnull exactly when releasable is true. Catalogue migration, reinterpretation and automatic deletion of restrictions are unsupported. Configuration pins select this candidate. The trusted boundary comprises the protected registry, local private materialization store, mediator and independently authorized constant-response service. Evaluators, external storage/logs, connectors, redirects and onward recipients are outside that boundary. MATERIALIZE stores only inside that private boundary and makes no external call.

The host installs exactly one authoritative flow registry/configuration per principal and retains its complete history. A second configuration, registry id, actor alias or initialization cannot reset claims or consumed releases. Configuration migration needs a separate explicit contract; this profile refuses it. The pure consumer checks the supplied bodies; the protected host selects the actual installed registry and current state.

A source descriptor is `{provider,source,record_type,record_id,revision,content_digest,scope,restrictions}`. Restrictions are sorted unique catalogue ids and all apply to that exact scope. Its identity is `digest("flow-source",descriptor)`. This descriptor claims exact immutable provider provenance; the host authenticates its classification and real delivered bytes. A digest does not prove truth or completeness.

A context is `{id,actor,scope,purpose,revision,ceiling,restrictions,origins}`. Its digest is `digest("flow-context",context)`. Ceiling and restrictions are sorted unique catalogue ids; origins are complete source descriptors sorted uniquely by their source digest. Restrictions equal the union of origins plus any imported sending-context restrictions, and never shrink. Every restriction's scope equals context scope. Context creation fixes actor, scope, purpose and ceiling. Initial revision is `"1"`; each admitted READ or IMPORT advances it even when the union is unchanged. MATERIALIZE and EXPOSE change registry state without advancing delivered-state context revision.

The complete initial reachable inventory is selected by the host and includes initial prompts, memory, tools, retrieval and restored state. Creation establishes an empty dormant context before any prompt, tool, memory, retrieval, restored state, work trigger or selection becomes reachable. initial_sources is exactly []; the protected admission attestation binds that empty inventory and the declared surface coverage. Each initial source, including the original independent work trigger and selection, then enters through authorized READ or IMPORT. The first such transition activates reachable work. MATERIALIZE refuses ACCESS_NOT_ESTABLISHED while context revision remains "1". A source inventory supplied directly to creation cannot bypass read access or claim recording. A user or agent asserting an empty inventory does not establish independence. Unknown or unadmitted state withholds creation. The host establishes that every actual read/import joins this registry and that current context state cannot roll back.

## FLOW-002. Expected-revision transitions and ordinary access authority

`flow-step` receives `{schema,specification_pin,configuration,state,state_digest,event,host_evidence,response_authority}`. After outer shape admission, independently authorize the current reader before any protected result or echoed state can be returned. response_authority is the closed no-budget access-input profile below, with proposal.executor.role equal to configured response_role, the configured response_operation and STRING/IDENTITY admission_subject equal to `digest("flow-response-subject",{configuration_digest,state_digest,event_id,event_digest,protected_channel})`, using the supplied event/host-evidence digest. Its principal/interface match configuration and its host-supplied clock is current and AVAILABLE; it need not equal a replayed event clock. A response-access refusal returns only generic `{status,code,path}`, never state, receipt or diagnostics. Historical event records do not retain or reuse this current reader authority. Protected output routing and authentic current reader identity remain host responsibilities. Null state requires null state digest. The first admitted event is CREATE_CONTEXT with expected_revision `"0"` and null expected_state_digest. It establishes registry revision `"1"`. Every admitted event advances the global registry revision by one, independently of context delivered-state revisions. Events have `{schema,id,kind,expected_revision,expected_state_digest,clock,payload}`. The available event clock uses the configured source, cannot precede the retained last clock, and is explicit input. A fresh expected revision or state digest mismatch refuses REVISION_CONFLICT. Every admission or denied access/exposure refusal returns the exact unchanged supplied state and digest, records no event, consumes no claim or release, and exposes no content. Malformed outer shape uses the generic protocol refusal without trusting its state body. Denials do not consume event capacity; protected host audit of attempts remains separate.

Payloads are closed:

```text
CREATE_CONTEXT = {context_id,actor,scope,purpose,ceiling,initial_sources}
READ = {context_id,intent_id,claim_id,source,access_authority}
IMPORT = {sender_context_id,receiver_context_id,artifact_id,intent_id,claim_id,
          transfer_authority,access_authority}
MATERIALIZE = {context_id,artifact_id,types,fields}
EXPOSE = {requirement_id,authority_projection}
```

A control subject is `digest("flow-control-subject",{configuration_digest,event})`, where the event projection omits only payload.access_authority and payload.transfer_authority when present. READ authority targets configured control_interface/access_operation; IMPORT access targets the same access operation and transfer authority targets transfer_operation. Each complete ordinary authority proposal has exactly one native field, admission_subject, whose STRING/IDENTITY value equals this digest. Its principal, executor actor, operation/interface and available clock match the configured principal, receiving/sending context actor, selected operation and event clock exactly. All response, READ, IMPORT and EXPOSE authority profiles have no shared budgets in work class, selected step or envelope limits and must produce required_budgets:[]. Otherwise refuse UNSUPPORTED_RELATION before accepting any readiness result. These operations add no reservation bypass. EXPOSE records flow permission and its claim; business connectors separately require their existing exact lifecycle permit, fresh dispatch authorization and durable intent, joined by the protected host before invocation. All access/transfer/response inputs contain no nonempty flow requirement or basis. Optional flow_bases may be omitted or explicitly []; nonempty flow_bases violates this closed access shape, while a nonempty envelope flow_requirements declaration refuses UNSUPPORTED_RELATION. Omitted and explicit empty remain distinct retained evidence. Independently authenticate and evaluate every supplied access/transfer input; READY_FOR_RESERVATION establishes only this exact mediator operation. It does not establish actual exposure. A current policy withholding with code AUTHORITY_NOT_ESTABLISHED maps to standalone ACCESS_NOT_ESTABLISHED; all other ordinary refusal codes retain their spelling. EXPOSE uses the same mapping for its outgoing authority result. IMPORT evaluates receiver access first and returns its first refusal, then evaluates sender transfer; each evaluation follows ordinary authority phase order. Successful receipt arrays retain receiver-access then sender-transfer result/evidence digests.

Within one configuration, descriptors with identical provider/source/record_type/record_id/revision/scope coordinates must have identical complete bytes wherever retained; conflicting immutable issuance descriptors refuse DEPENDENCY_MISMATCH. New source classification needs a new provider revision.

Host evidence is `{configuration_digest,event_subject_digest,selection_evidence,attestations}`. Each attestation is `{kind,subject_digest,provider,source,channel,evidence_ref}`. Attestations sort uniquely by complete canonical bytes and match configuration provider/source/protected channel. Required kinds and subjects are INITIAL_INVENTORY over the complete creation payload, SOURCE_CLASSIFICATION over the READ descriptor, and MATERIALIZED_CONTENT over complete MATERIALIZE types/fields. Attestation domains are `digest("flow-initial-inventory",creation_payload)`, `digest("flow-source",source_descriptor)` and `digest("flow-materialized-content",{types,fields})` respectively. All event kinds require event_subject_digest equal to the exact flow-control-subject digest defined above, including EXPOSE with its complete authority projection and no additional omissions. Missing required evidence refuses EVIDENCE_UNAVAILABLE; wrong or additional attestations refuse DEPENDENCY_MISMATCH. Authenticity and complete coverage are host premises, not inferred from these strings.

READ validates source scope, current access and the receiving ceiling, then atomically retains the complete origin, accumulated union and globally unique possible-delivery claim before making any content, partial result or existence-sensitive error reachable. IMPORT validates the retained artifact, both current context actors and both authority inputs, then unions the artifact's historical restrictions/origins with the sending context's current restrictions/origins into the receiver. The receiving ceiling must admit the entire union. The transfer's trigger and selection are governed by the sender's current context. IMPORT offers no release exception. The atomic transition records receiving union and a unique possible-delivery claim before exposure.

MATERIALIZE admits the complete nominal type declarations and native field values under existing scalar rules, retains an unused artifact id, and copies the exact current producer context digest/revision, restrictions and origins. An artifact is `{id,context_id,context_revision,context_digest,types,fields,restrictions,origins}`; its digest is `digest("flow-artifact",artifact)`. Its origin and context bindings are deterministic, not caller-selectable. It authorizes no outgoing action.

EXPOSE requires the expanded outgoing authority clock to equal the complete AVAILABLE event clock exactly, rehydrates and evaluates its exact outgoing authority projection under FLOW-003/004, then records a unique possible-exposure claim and consumes the selected release act before the host exposes bytes. The host retains all participating access, source classification, context, policy, recipient and withdrawal writers under the coordinator through the immediate first-exposure boundary. A crash before the atomic claim/union commit leaves no new claim and permits a fresh authorized attempt. A crash after that commit, even before observed invocation, retains POSSIBLE_EXPOSURE and consumed release. No same-intent automatic recovery or new-claim retry is defined; protected referral and explicit later recovery policy are required. Later delivery by a custody recipient needs its own current boundary or an explicitly limited custody-transfer claim. Business acceptance, rejection, failure, timeout or uncertainty cannot unconsume this claim. This first profile has no automatic reset, even if later evidence establishes no exposure; a new release is required.

## FLOW-003. Complete reconstruction, exposure projection and replay

Core is `{configuration_digest,revision,last_clock,contexts,artifacts,claims,consumed_release_acts}`. Contexts and artifacts sort uniquely by id; claims sort uniquely by id; consumed act digests sort uniquely by UTF-8. Each claim is `{id,intent_id,status,kind,context_id,recipient,channel,purpose,subject_digest,release_act_digest}` with kind READ, IMPORT or EXPOSE and nullable release_act_digest. For READ and IMPORT, context_id and recipient equal the receiving context id, channel equals configuration.control_interface, purpose equals receiving context.purpose, subject_digest equals the flow-control-subject digest and release_act_digest is null. For EXPOSE, context_id equals the sender context id, recipient is the native selected recipient scalar, channel/purpose come from the selected requirement, subject_digest equals the flow-disclosure-subject digest, and release_act_digest is the selected admitted release act digest or null. status is exactly POSSIBLE_EXPOSURE. intent_id is the stable host-selected logical delivery intent, distinct from the event and attempt claim identities. For READ/IMPORT it comes from the payload; for EXPOSE it comes from the selected requirement and signed disclosure subject. Claim ids and intent ids are each globally unique. A fresh claim cannot repeat an unresolved intent. New independent work requires a genuinely new host-selected intent, not renaming a retry. A claim always means possible exposure, not business completion or proof of delivery. Claim identities are unique across the complete registry. A release act can appear in only one EXPOSE claim, including across contexts and occurrences.

State is `{schema,specification_pin,core,records}`. Each record is `{event,host_evidence,event_digest,receipt,receipt_digest}`. Event digest is `digest("flow-event",{event,host_evidence})`. Receipt is `{schema,event_id,event_digest,state_before_digest,revision,core_after_digest,decision,authority_result_digests,authority_evidence_digests,protected_channel}`. Its digest is `digest("flow-receipt",receipt)`; core_after_digest uses `flow-core`, and complete state digest uses `flow-state`. Decisions are CONTEXT_CREATED, READ_RECORDED, IMPORT_RECORDED, ARTIFACT_RECORDED and EXPOSURE_RECORDED. Result and evidence digest arrays retain all admitted ordinary evaluations in access/transfer order or the one outgoing evaluation.

EXPOSE's authority_projection has the complete ordinary authority input shape except that its single selected flow basis omits exactly the state member. State digest, configuration, selection, release subset and every other optional-member presence remain. Reconstruct that omitted member from the complete locally validated pretransition state; require the supplied digest and configuration to match. Recompute complete outgoing authority and evidence digests from the expanded body. Retain only the projection in history to avoid recursively embedding prior histories. No arbitrary absent body is fetched or supplied by a digest assertion.

Reconstruct every event, host attestation, ordinary authority evaluation and receipt in order. Compare complete final core/history and all digests. Missing, reordered, impossible or altered history refuses STATE_INVALID; a supplied outer state digest mismatch refuses DIGEST_MISMATCH. Historical authority is evaluated at its retained clock. Implementation may reuse exact internally verified prefixes during one public evaluation. No caller-provided trust flag, digest alone or persistent cache can establish validation. This avoids recursive reevaluation without changing the admitted result.

After complete state admission, an exact event/host-evidence replay returns the historical receipt and current state with replay:true. It changes no revision and authorizes no new fetch, read, import or send. Changed bytes under an existing event id refuse REPLAY_CONFLICT before checking fresh revision, clock or authority. Present read access to protected replay evidence requires separate host authorization.

## FLOW-004. Outgoing declarations, exact artifact and current policy

Ordinary envelopes gain optional flow_requirements, and ordinary inputs gain optional flow_bases, each zero or one. Missing selected basis refuses EVIDENCE_UNAVAILABLE; unrequested nonempty basis refuses DEPENDENCY_MISMATCH. Supplied empty and omitted members remain distinct canonical evidence. Independent human leaves cannot declare nested flow requirements or bases.

A requirement is `{id,step,configuration_digest,context_id,artifact_id,intent_id,claim_id,recipient_field,channel,purpose,policy,release_decision_requirement_id,sources}`. release_decision_requirement_id is nullable. Sources are `{policy:{requirement_id,digest_field},recipient:{requirement_id,recipient_field,channel_field,purpose_field,effective_field},release_selection,release_effectiveness,blockers}`. Release-selection mapping is nullable or `{requirement_id,act_id_field,act_digest_field,subject_digest_field,claim_id_field}`; effectiveness is nullable or `{requirement_id,act_id_field,effective_field}`. Both are nonnull exactly when a release requirement is selected. Blocker ids sort uniquely.

Policy is `{id,revision,configuration_digest,entitlements,release_rules}` with complete rows sorted uniquely by canonical bytes. Entitlement is `{restriction_id,scope,recipient,channel,purpose}`. Release rule adds release_role to the same fields. Its digest is `digest("flow-policy",policy)`. All restriction references resolve against immutable configuration; scope and releasability cannot be changed by policy. Unknown selectors or unsupported nominal types refuse at ordinary admission phases.

Basis is `{requirement_id,configuration,state,state_digest,selection,released_restrictions}`. Selection is `{configuration_digest,state_digest,revision,provider,source,channel,at,status,selection_evidence}`, with status AVAILABLE, UNAVAILABLE or CONFLICTING. Its coordinates match configuration and its at equals the evaluation clock for current reliance. The host authenticates that this is its latest authoritative nonrollback registry selection. Stale or unavailable selection does not authorize a disclosure. Complete historical self-consistency does not establish freshness.

Bind selected step, configuration, artifact, sender context, actual executor, principal, scope and native recipient selector exactly. Context.scope equals envelope.scope.id; context.actor equals proposal.executor.actor and configuration.principal equals envelope.principal. The context purpose remains fixed and signed in context_digest. Outgoing requirement purpose is checked separately against recipient entitlement and release policy; it need not equal the original read purpose. This permits the selected internal-planning context to release exact compensation content for an authorized benchmarking purpose. Artifact types equal complete work-class types; artifact fields equal complete native proposal fields. Its producer snapshot is the exact context reconstructed at its materialization event. The current sender context must own that artifact's context_id in this first profile; cross-context reuse proceeds through IMPORT and new materialization. Outgoing restrictions are the union of artifact restrictions and current sender restrictions. An old clean artifact therefore cannot carry a restricted sender's selection or send trigger to a clean recipient.

Recipient source fields equal the native recipient scalar, declared channel/purpose and effective:true. Current policy source digest equals the complete declared policy. Every ordinary source and blocker uses CLOCK, zero freshness and PROPOSE_AND_DISPATCH and belongs to the same step's SOURCE_REQUIREMENTS gate. Each unreleased restriction needs an exact policy entitlement. A bank restriction with releasable:false cannot be released by any human act or model judgment.

## FLOW-005. Supplementary human release and one disclosure

A nonempty sorted released_restrictions subset requires the declared distinct same-step supplementary HUMAN requirement. It is a subset of the complete outgoing union; each item is releasable in the immutable catalogue and has an exact current release-rule row. A null release requirement requires an empty subset and null release source mappings. The first profile forbids selecting a release requirement with an empty subset. Every unreleased restriction still requires recipient entitlement.

Add the computed context binding `{kind:"FLOW_DISCLOSURE",requirement_id,type_ref}`. Exactly one supplementary leaf field selects it and has a complete matching STRING/IDENTITY nominal declaration. It computes `digest("flow-disclosure-subject",{principal,configuration_digest,policy_digest,context_digest,artifact_digest,work_class_digest,instance,occurrence,step,interface,operation,fields,recipient,channel,purpose,intent_id,claim_id,released_restrictions})`. Every value comes from admitted bodies. It excludes final outer envelope/proposal digests, human acts and future authorizations/events. The leaf's ordinary fixed nonnull identity_field and validity_fields remain exhaustively bound under AUTH-008. Release approval is an independent act; assessment review remains the sole outer gate when selected. When no assessment is selected, the release leaf may itself satisfy the outer human gate while the ordinary send grant remains independently required. This profile adds no second human content-review act to the compensation example. The human principal/role equal the selected configuration principal and current release rule's role. Existing current remit, signing authority, human return and withdrawal checks still apply.

Release selection's complete current fields equal the admitted act id/digest, computed disclosure subject and claim id. Effectiveness separately binds that act id and effective:true. Missing, changed, superseded or withdrawn release does not satisfy the gate. Permission regrant can restore current remit only if the release remains selected, effective, unexpired and unused; it does not undo withdrawal or consumption. A previously consumed act or existing claim withholds even if presented through another context, occurrence or fresh invocation.

Release permits only this exact disclosure. It changes no source classification, context restriction, artifact origin or downstream forwarding right. A changed context, native content, recipient, channel, purpose, subset, policy or claim changes the signed subject. Current registry revision is fenced separately, so unrelated registry activity need not invalidate this subject. Human authority evidence stays in protected host control state outside the sending agent's reachable context until first exposure; giving it to that agent is another admitted read that changes the context and invalidates the earlier subject.

## FLOW-006. Checks, exposure fence and deterministic refusal

Use inherited five authority phases. Phase 1 admits shape, scalar types and directly resolvable nominal bridges. Phase 2 admits declarations, exact selected bases, configurations, reconstructed state, reference inventories and finite bounds. Phase 3 binds complete content, context, recipient and computed human subject. Phase 4 authenticates ordinary and human acts. Phase 5 joins complete ordinary source inventory before current flow policy checks. Sorted/duplicate data errors are INPUT_INVALID; unknown references are REFERENCE_INVALID; unsupported profiles are UNSUPPORTED_RELATION; exact known mismatches are BINDING_MISMATCH or DEPENDENCY_MISMATCH under the inherited phase order.

Successful FLOW checks use subject digest `digest("flow-query",{requirement_id,context_digest,artifact_digest,intent_id,claim_id,recipient,channel,purpose,at})`. Policy reasons are FLOW_UNAVAILABLE, FLOW_STALE, FLOW_CAPACITY_EXHAUSTED, FLOW_DEPENDENCY_CHANGED, FLOW_RECIPIENT_NOT_ENTITLED, FLOW_RELEASE_NOT_ESTABLISHED and FLOW_CLAIM_CONSUMED. Each reason retains the same exact failed-check subject/reference/instant and participates in deterministic ordinary reason ordering. A missing registry basis is admission EVIDENCE_UNAVAILABLE, while unavailable authenticated selection is current FLOW_UNAVAILABLE. FLOW_UNAVAILABLE covers unavailable or conflicting current selection. FLOW_STALE covers an available selection at another instant or an evaluation before retained last_clock. FLOW_CAPACITY_EXHAUSTED covers inability to retain the next event/claim. FLOW_DEPENDENCY_CHANGED covers a current policy digest or recipient/channel/purpose source value differing from the admitted body. FLOW_RECIPIENT_NOT_ENTITLED covers a false current recipient effective field or a missing exact entitlement for an unreleased restriction. FLOW_RELEASE_NOT_ESTABLISHED covers nonreleasable restrictions, missing exact release rules/role, or changed current release selection/effectiveness. FLOW_CLAIM_CONSUMED covers an existing claim, an existing logical intent or a consumed selected release act. Emit every independently checkable failed policy reason after complete source inventory. Flow policy cannot replace ordinary access, contact, assessment or execution authority.

SOURCE_REQUIREMENTS authorization additionally retains a flow fence row `{requirement_id,configuration_digest,state_digest,revision,context_digest,artifact_digest,policy_digest,intent_id,claim_id,release_act_digest}`. All current context, source, policy, recipient, release-selection, withdrawal and first-exposure writers join the declared coordinator. Every finite current source/recipient/release/remit end clips authorization expiry. Source, holdings and flow fence rows share the existing combined 64-member projection bound. A read before exposure changes the sender context and invalidates a release for the prior context. A change after established exposure cannot recall it or rewrite historical authority.

Refresh may change only existing allowed clocks/observations/evaluation point and the complete current flow registry basis, as defined for holdings. Configuration, native content, selected artifact/context/intent/claim, release subset and all human bodies remain immutable. Fresh state may include unrelated context activity; changed sender state must satisfy new computed bindings and cannot reuse an old release. EXPOSE consumes claims inside the same serialized registry used by the fence; a preflight check alone establishes no ordering.

## FLOW-007. Retained work and exact optional presence

Every authority-evidence projection includes flow_bases iff supplied, including []. Reservation, permit, dispatch, withholding and restart paths that manually reconstruct evidence use the same rule. Retain complete original authority bodies at their historical clocks. Recompute bindings and results on restart; resealing outer hashes cannot repair a stripped origin or invalid release. Exact replay produces no new model assessment, source read or connector invocation.

Flow-aware operations require SOURCE_REQUIREMENTS for lifecycle dispatch. Completion remains the native business completion contract and never retroactively establishes that a connector saw no content. Referrals, errors, receipts, audit exports, reviewer interfaces and logging routes themselves require recipient admission. A deployment installs an exhaustive protected interface/operation-to-recipient mapping before exposing any route. Every mapped route requires the selected exact flow profile; missing declarations, alternate credentials, redirects or multi-recipient connectors are rejected by that host route. This first profile covers one immediate custody recipient per native operation and ends its guarantee at that transfer. A provider performing delayed onward delivery needs another mediated current boundary; the first-profile route refuses such an undeclared chain. Pure ordinary inputs without a selected flow profile retain inherited semantics and establish no mediated deployment.

Detailed refusal evidence remains protected; a clean host-owned constant response has independent provenance and receives no protected diagnostics from a restricted agent context. Its exact UTF-8 body is "Unable to process this request." with no trailing newline. The source is a protected immutable host constant, and destination/request identity comes only from the original independently admitted client request and current client authority. The constant-response service accepts no restricted agent text, explanation, context identity or diagnosis. It uses a separately admitted clean context whose authorized inputs are that constant and independent request. Protected internal diagnostics never enter this response context. This is a transport status response, not permission to send an otherwise unapproved business message.

## FLOW-008. Capacity and exercised host scope

The profile bounds configuration to 64 restrictions, registry to 16 contexts, 64 artifacts, 128 claims and 128 events, each context to 64 origins, and standalone flow-step input to 16,777,216 canonical bytes. Complete authority remains at most 1,048,576 bytes and independent human input at most 262,144. Closed-shape maxima refuse SCHEMA_INVALID; supported-shape byte/projected-state maxima refuse LIMIT_EXCEEDED. The selected adapter flow route bounds its raw JSON-line frame to 17,825,792 bytes before parsing and JSON nesting to 128 containers. The general local adapter is a trusted fixture transport, not an authenticated public ingress; the protected flow host supplies this bounded route and current reader check. State and authority bytes remain subject to their smaller applicable canonical bounds. Because every claim consumes an event and creation consumes at least one nonclaim event, the independent 128-claim ceiling cannot be reached before the 128-event ceiling in a valid history; never forge an unreachable state to claim that boundary was exercised. Exhausted history preserves replay/export/reconstruction but withholds new flow authority as FLOW_CAPACITY_EXHAUSTED. No pruning, history loss, silent new context or alternate registry extends that capacity.

The host authenticates identities, classifications, initial inventories, actual source bytes, current selections, recipient binding and complete participating writers. It mediates and isolates every declared reachable prompt, memory, tool, retrieval, cache, file, summary, delegation, evaluator, connector, log, error, metadata, audit and referral route. Unmediated routes remain explicit gaps. A state digest cannot prove actual isolation, provider forgetting, nonrollback durability or complete writers. The apparatus claims no timing/covert-channel protection, semantic inference prevention, arbitrary malicious ingress or production integration.

## Deterministic standalone refusal order

Outer shape/raw route admission precedes current response-reader authority. After current reader authorization, check candidate/configuration and complete state, exact event replay, expected revision/digest, available ordered event clock, exact host evidence, retained-event capacity, payload references/target/ceiling and current access/outgoing authority, then projected context/artifact/origin/claim capacities. A null-state noncreation event refuses STATE_INVALID. Duplicate context creation refuses DEFINITION_CONFLICT; unknown contexts/artifacts, reused artifact or delivery intent/claim identities, conflicting immutable source descriptors and wrong scopes refuse DEPENDENCY_MISMATCH. Unknown catalogue restrictions in configuration refuse DEFINITION_INVALID; unknown source/ceiling restrictions refuse REFERENCE_INVALID. Unsorted/duplicate inventories refuse INPUT_INVALID. A ceiling failure refuses ACCESS_NOT_ESTABLISHED. Invalid materialized native scalar/type declarations use TYPE_INVALID or REFERENCE_INVALID. Projected finite overflow refuses LIMIT_EXCEEDED. All post-reader refusals echo unchanged state/digest. No failed transition consumes a claim/release or calls an exposure provider.
