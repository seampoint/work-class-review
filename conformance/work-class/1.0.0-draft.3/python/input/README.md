# Work-class specification 1.0

Identity: `seampoint.work-class/1.0.0-draft.3`. This open review candidate defines deterministic governance for bounded work. Read `Specification.md` first, then the profile document that matches the work class.

This is an unqualified development candidate. Its files begin as an identity-preserving draft 2 baseline and are being migrated under the draft 3 contract proposal. The copied draft 2 review reports and cases are historical inputs, not draft 3 verification or qualification evidence. Draft 2 remains frozen at its own identity and pin.

This README is the informative index. The manifest binds the complete candidate distribution, including this index. Every other manifest-listed file is normative.

Candidate construction note: The conformance fixtures C3-SUCC-015 and C3-SUCC-016 now supply the peer gate's complete source declarations in their authority inputs. Their selected ungated operation and expected judgments are unchanged. This apparatus note adds no requirement.

The manifest covers linear work, typed constraints, business authority, cumulative aggregates, shared reservations, choice and bounded loops, activity deadlines, structured parallel work and frozen fan-out. `LIFECYCLE.md` defines the common governed transition, and `COMPOSITION.md` defines the cumulative profile family. Repeated expansion passes, dynamic fan-out, compensation, general cancellation, child-work invocation and distributed execution are excluded and recorded as explicit exclusions.

`OBSERVATIONS-AND-DISPATCH.md`, `EXCLUSIVE-KEY-HISTORY.md`, `COMPLETION-AND-REFERRALS.md` and `SOURCE-CORRECTIONS.md` define the source observations, dispatch refresh, attributed history, terminal evidence, referrals and external corrections used by the equipment specimen. They add deterministic evidence rules; the host still supplies authenticated source facts, complete provider history and conditional writes.

The contract is self-contained and can be implemented from these documents alone. Source mappings in the conformance package explain retained semantics; they do not add requirements to this contract.

`RECOVERY.md` defines explicit disposition of disputed evidence, retained contingent exposure, human-issued bounded exception policies and application to dependent work. Ordinary unknown outcomes retain their existing behavior. Recovery preserves historical records, current budget ceilings and source-selected terminal consequences.

`TIMING.md` defines bounded observation age, immutable initial-event anchors, duties retained before target activation, first qualified withholding and possible-dispatch timers, and current clocks at permission boundaries. These extensions retain original event bases through expiry, replay, restart and recovery.

`INDEPENDENT-HUMAN-DECISIONS.md` defines separate human authority evidence, selection of an admitted decision by an execution gate, complete source-vector dispatch guards, historical authorization-revision completion bindings and corrections requiring fresh independent decisions. These extensions preserve the distinct authority of each principal and the provider's commitment obligations.

The adapter protocol uses canonical JSON lines and the operations `capabilities`, `validate`, `evaluate`, `aggregate-step`, `holdings-step`, `flow-step`, `deploy`, `step`, `readback` and `check-evidence`. A response includes a typed decision, refusal when applicable, receipts and complete next state. Admission failures leave state and reservations unchanged.

`EXTERNAL-DEPENDENCIES.md` describes facts and capabilities supplied by an organization or host. Those records close the description of the boundary. They do not qualify a production deployment. The reference host qualifies serialized single-process transitions and contention only.

The candidate is a draft, not an adopted standard or a production-readiness claim. The normative specification is available under the Community Specification License 1.0 recorded at the repository root. Any normative change creates a new candidate identity and preserves this candidate’s results.

Current permission holdings are defined in [HOLDINGS.md](HOLDINGS.md), with the separate `HOLDINGS_TRANSITIONS` role and `holdings-step` operation. The first profile covers incompatible permissions; prerequisites and approved exceptions remain outside this profile.

Exact-content assessments and mandatory attributable human review are defined in [ASSESSMENTS.md](ASSESSMENTS.md). The first profile binds complete native content, supporting context, rubric, model findings and human dispositions to one exact occurrence. It uses existing authority and source-vector commitment, adds no model API, and grants no authority from a model verdict.

Accumulated context restrictions, authorized reads and imports, exact artifacts and one-use human disclosure are defined in [INFORMATION-FLOW.md](INFORMATION-FLOW.md). The first profile uses a principal-wide protected registry and one immediate custody recipient. Current access, complete host mediation and lifecycle execution remain independently required.
