# Completion, lookup and referrals

The explicit independent-decision, source-vector, dynamic completion and correction alternatives in [INDEPENDENT-HUMAN-DECISIONS.md](INDEPENDENT-HUMAN-DECISIONS.md) govern when selected. All inherited carrier inventories and behavior remain unchanged when those members are absent.

Normative draft 3 contract. Status: `DRAFT_NOT_ADOPTED`; claim ceiling: `APPARATUS_ONLY`. Bundled schemas govern closed shape admission. The rules below govern semantic admission, deterministic decisions and retained evidence. Provider truth, durable coordination and source fidelity require separate evidence.

## 1. Complete completion declarations

Every shape is closed. Scalar types, values, identifiers, digests and valid whole-second UTC dates retain the current candidate semantics. Extend the completion carrier with explicit `terminal_policy`, LEGACY_NONTERMINAL or STOP_RETAIN. Final draft 3 definitions explicitly migrate inherited carriers to LEGACY_NONTERMINAL; equipment uses STOP_RETAIN. No active old-pin state is relabelled.

STOP_RETAIN requires provider_record_identity `{field,type_ref}`, event_time_identity `{field,type_ref}`, additional_fields and lookup. provider_record_identity names an IDENTITY or STRING field holding the generated provider event id. event_time_identity names an INSTANT field holding the provider event timestamp. additional_fields is a sorted unique array of at most 64 `{name,value}` constant typed fields. These declarations are disjoint from status, request-bound evidence fields, provider-record identity and event-time identity. Their exact union is the full required completion field inventory, bounded to 66 fields at static admission; exceeding that semantic limit is LIMIT_EXCEEDED. All referenced types belong to definition.types. Additional completion-only types are included in the authority projection whenever declared in authority_type_refs; no native request field is invented to carry them. The authority work-class projection always includes the complete STOP_RETAIN carrier and all its referenced nominal types, independently of exclusive-key declarations. Inherited LEGACY_NONTERMINAL carriers retain the existing projection rule. The full projected carrier must equal the selected definition carrier; a caller cannot substitute another completion policy.

Every permit for STOP_RETAIN retains its complete original authority_basis and authority result commitment, whether or not the step declares dispatch_gate or exclusive keys. Restart independently admits that basis and checks its exact projection, proposal, occurrence, executor, request, clock, result and permit expiry.

STOP_RETAIN optionally declares `generated_fields`, a sorted unique array of at most 64 closed `{name,type_ref}` rows. Every named field is required in the complete native evidence and has the declared nominal scalar type and a valid value for that type. Its value comes from the provider's result; no preknown request value or constant supplies an equality check. These fields are disjoint from request-bound fields, status, route label, provider-record identity, event-time identity, additional constant fields and authorization-revision bindings. The complete distinct inventory remains bounded to 66 fields. Include every generated declaration and nominal type in the complete authority projection and correction inventory. Preserve the exact distinction between an omitted declaration and an empty array. LEGACY_NONTERMINAL has no generated_fields member. Type validity establishes neither provider authenticity nor a business disposition; the source-selected provider, record type, success values and host authentication premises still govern those claims.

A prior-effect binding may select any field in the exact source step's complete declared STOP_RETAIN inventory, including a generated field. Its nominal type must equal the target request field's nominal type. The existing UNIQUE_COMPLETED_ANCESTOR selection and exact retained MATCHED native-evidence basis remain required. The binding reads the unique retained native fact, never a current provider lookup, a latest record or the source request. Inherited completion profiles retain their request-bound source-field rule. A separate work instance, including a filing amendment, must receive separately authenticated prior-filing evidence through its own source requirements; this binding does not create a cross-instance ancestor relation.

Extend nativeEvidence with optional nullable provider_record_id and provider_revision. STOP_RETAIN EFFECT_ESTABLISHED requires nonnull values to establish a match. Missing/null identity or revision is a retained completion mismatch, never an inferred generated event. provider_record_id equals the scalar value in the declared identity field; event_time equals the value in the declared INSTANT field. Provider/source/type equal the carrier's effect declaration. Every request-bound value equals the complete retained request. Every additional value equals its source-selected typed constant. Status equals a declared success/failure value. Collections remain empty for equipment.

A typed provider link uses a nominal IDENTITY type with a value equal to the canonical JSON string encoding of `{provider,source,record_type,provider_record_id}`. The equipment approval link therefore identifies the exact approval register and AP-091. An unqualified AP-091 string fails. This nominal scalar does not fetch the linked record or establish its authenticity.

Well-formed evidence with missing, extra, duplicate, unknown nominal, incorrectly nominally typed or unequal fields is retained as UNEXPECTED. Duplicate native field names are completion mismatches for this terminal profile, including when values agree. Transport/canonical/invalid raw dates and illegal assertion combinations still refuse before state mutation. A malformed known scalar within a field is a completion mismatch; the complete supplied evidence is retained without treating it as a usable typed value. No such field can satisfy a request or consume keys. Inherited profiles preserve their existing admission and classification behavior.

Provider record identity is `{provider,source,record_type,provider_record_id}`. Same identity and identical complete native fact is DUPLICATE evidence; For governed STOP_RETAIN evidence, evidence_id, evidence_ref and observed_at are receipt metadata excluded from native-fact equality. LEGACY_NONTERMINAL and foreign evidence retain the inherited exclusion of evidence_id and evidence_ref only. Same identity with changed provider fact is CONFLICTING. Different record identities for one native_operation_id are CONFLICTING additional execution evidence. This comparison includes native provider_revision and record_digest without lexical latest-wins. A caller cannot change evidence_id to hide conflicting provider identity. Conflicting evidence remains retained with its exact original bodies.

A governed STOP_RETAIN outcome retains source_event as the complete original governed EFFECT_OBSERVED event, admitted by governedEffectObserved. It is part of the outcome digest. Its event_id, runtime-event digest, permit, dispatch and native_evidence exactly match the outcome and retained permit/dispatch. Retain the full supplied completion_authorization, budget_inputs, original expected state revision and digest, clock_revision and activation_clocks. Restart checks these original bindings against the corresponding receipt, preceding state and retained reservation transition and evaluates supplied no-effect authority under the original rule. It never infers omitted authorization or registry input. source_event is required semantically for STOP_RETAIN and absent for LEGACY_NONTERMINAL outcomes; no old-pin checkpoint is relabelled.

## 2. Source-selected terminal failure

STOP_RETAIN handles UNKNOWN, UNEXPECTED, CONFLICTING, failed declared result, unsafe NO_EFFECT and lookup failure by stopping the work instance. The occurrence remains OUTCOME_UNKNOWN for UNKNOWN and BLOCKED_DISPUTE for mismatches/conflicts/failed results. An occurrence already BLOCKED_DISPUTE remains blocked after later unknown evidence or lookup failure. A first terminal record stores the occurrence status immediately after its own event; a native UNKNOWN result following a gated disputed dispatch therefore records BLOCKED_DISPUTE even though its reason is UNKNOWN_OUTCOME. A later independent block does not rewrite an earlier terminal record. The complete outcome and reasons remain retained. No successor, second dispatch, implicit correction, rollback, automatic release or assertion about remote current status follows. Exact completion alone can consume the full key set through the existing atomic reservation transition.

Native EFFECT_OBSERVED preserves the existing classification-specific disposition and reasons: UNKNOWN uses OUTCOME_RETAINED/UNKNOWN_OUTCOME; UNEXPECTED uses DISPUTED/UNEXPECTED_EFFECT; CONFLICTING uses DISPUTED/CONFLICTING_EFFECT; declared FAILED uses FAILED/DECLARED_FAILURE. Applicable registry dispute reasons still add under LIFE-006. STOP_RETAIN additionally stops the instance and retains terminal/referral evidence. A declared failed result cannot consume keys as successful; its registry transition retains disputed exposure and HELD keys. A successful exact effect follows ordinary completion and may complete the linear instance. No new terminal failure record is required for success. An affirmative NO_EFFECT record never creates a retry in STOP_RETAIN, even if a separate accepted no-effect authority record is supplied. It is retained under the applicable conservative classification and terminal rule. Lookup never substitutes for affirmative NO_EFFECT evidence.

A late exact native event may reconcile a past effect and consume held keys atomically. An OUTCOME_UNKNOWN occurrence may close as SUCCEEDED with late:true and no selected relationship while its instance remains STOPPED. A prior BLOCKED_DISPUTE occurrence remains blocked; retain its exact late outcome and DEPENDENCY_DISPUTED/LATE_EFFECT reasons without erasing the dispute. It cannot remove earlier disputed evidence or terminal records, reopen the instance, create routing or invoke a connector. Late conflicting evidence remains disputed. A first late conflict after a successful COMPLETE instance transitions it to STOPPED, retains the original completed row and receipt, and creates its first CONFLICTING_COMPLETION terminal record; no active row or new route is created. Exact duplicate facts leave COMPLETE unchanged. An already stopped instance uses the retained terminal cause and appends the new evidence, rather than replacing history.

## 3. Exact completion lookup

The completion.lookup declaration is exactly `{provider,source,record_type,namespace,key_projection}`. key_projection is a nonempty ordered array of at most 64 named proposal-field or typed constant projections using the exclusive-key projection shapes. Effective key names are unique. The equipment tuple lookup contains provider/source namespace and exact asset/work_order/inspection/approval values. Authoritative generated-event-id lookup can be declared by a separate source-selected query; this initial event uses the tuple declaration and accepts no substituted event-id key. Provider capability evidence retains both supported lookup modes as an external premise.

The exact derived query is `{instance_id,occurrence_id,permit_digest,dispatch_digest,authorization_digest,provider,source,record_type,namespace,key,at}`. at is the selected latest available lifecycle clock instant. authorization_digest equals the exact observed authorization digest on the referenced dispatch when that member is present; otherwise it is null. For a dispatch eligible to invoke a selected gated step, this is the nonnull digest of its exact retained authorization. An already retained gated dispatch whose receipt contains `LATE_OR_PROHIBITED_DISPATCH` and whose observed authorization claim failed the exact historical authorization check at `attempted_at` instead carries that claim, including null, solely for investigation under the claim-only exception below; it grants no send authority. A late dispatch with an otherwise valid historical authorization still requires reconstruction of that exact retained record. A selected step omitting `dispatch_gate` may omit the dispatch authorization member only under LIFE-003 and LIFE-008; if that step elects the inherited single-provider `AUTHORIZE_DISPATCH` carrier, its dispatch and query bind the exact retained nonnull authorization digest. Apply the same dispatch-derived value to `COMPLETION_CHECKED`, completion checks and terminal records. Null does not bypass a declared gate or invent a synthetic authorization. `query_digest` is `digest("completion-query",query)`. key contains sorted named complete typed values derived from the exact permit request/constants. No caller label determines the key.

A complete lookup record is exactly `{query,query_digest,status,observed_at,as_of,provider_revision,coverage,candidates,truncated,evidence_ref,provenance_digest}`. status is NOT_FOUND, UNAVAILABLE, AMBIGUOUS or OVERFLOW. coverage is COMPLETE, INCOMPLETE or UNAVAILABLE. observed_at equals query.at. Usable provider observations have valid as_of no later than query.at and nonnull provider_revision; zero-freshness equipment queries require as_of=query.at. UNAVAILABLE has null as_of/revision, coverage UNAVAILABLE, candidates:[] and truncated:false. NOT_FOUND has no candidates and truncated:false. AMBIGUOUS has 2..64 sorted unique candidate rows and truncated:false. OVERFLOW has exactly 64 sorted unique rows and truncated:true. Every candidate is exactly `{provider,source,record_type,provider_record_id,record_digest}` with nonempty provider identity and a complete record digest. Coordinates equal the declared provider/source/type. Candidate identities cannot repeat under changed digests. MORE than 64 is SCHEMA_INVALID, not a silently reduced set. OVERFLOW declares there are additional records that this bounded result cannot carry.

provenance_digest is digest("completion-lookup-provenance",the full lookup record with provenance_digest omitted). Its preimage includes the exact query, candidate inventory, coverage, revision and time. The host must independently authenticate this complete provider assertion and retain original returned bytes. Recomputing a digest proves binding, not completeness or provider truth. Wrong query/digest/provider/key/dispatch/date/provenance binding refuses BINDING_MISMATCH before a policy result. Valid INCOMPLETE coverage, stale as_of or unavailable evidence never establishes absence; it still terminalizes a possibly sent equipment instance as unproven.

Add COMPLETION_CHECKED event exactly `{schema,event_id,kind,instance_id,expected_state_revision,expected_state_digest,permit,authorization_digest,dispatch_digest,lookup,clock_revision}`. kind is COMPLETION_CHECKED. It is eligible only after an exact retained request may have reached the connector: SENT, UNKNOWN, REJECTED or accepted acknowledgement. The retained dispatch native_request must equal the permit native_request. Safe NOT_SENT with no accepted acknowledgement, before dispatch, another permit or dispatch, a claimed authorization_digest different from that retained on the dispatch, a prior admitted COMPLETION_CHECKED for this occurrence, or any conclusive native effect refuses PREREQUISITE_MISSING or BINDING_MISMATCH under ordinary binding precedence. A changed-request dispatch refuses BINDING_MISMATCH because the derived permit query does not cover that attempted request; direct attributable EFFECT_OBSERVED remains available under LIFE-010. Exact event replay remains allowed. A retained UNKNOWN native outcome does not block the first lookup. No fresh authorization is required to investigate an older uncertain attempt. An eligible gated dispatch uses its historical retained authorization even if it has since expired; a gated `LATE_OR_PROHIBITED_DISPATCH` row whose observed claim failed the exact historical authorization check at `attempted_at` uses that claim for correlation without treating it as authority. Every authorization record actually retained in state still independently reconstructs, even when its claim was stale or mismatched for this dispatch. A gated late row with a valid historical authorization requires exact reconstruction of that authorization. Neither case permits a new connector invocation.

NOT_FOUND and UNAVAILABLE yield COMPLETION_FAILED with UNKNOWN_OUTCOME and occurrence OUTCOME_UNKNOWN unless that occurrence is already BLOCKED_DISPUTE, in which case it stays BLOCKED_DISPUTE. AMBIGUOUS and OVERFLOW yield COMPLETION_FAILED with respectively COMPLETION_AMBIGUOUS or COMPLETION_OVERFLOW and occurrence BLOCKED_DISPUTE. Add LOOKUP_INCOMPLETE or LOOKUP_STALE for the applicable usable but unproven coverage/time. Every first stop on an occurrence stops the instance, consumes dispatch permission, retains exact lookup evidence and emits declared completion referrals. The first terminal record occurrence_status equals the occurrence status immediately after that lookup event; lookup does not clear an earlier dispatch prohibition. A later independent block does not rewrite that record. A first lookup after an earlier native UNKNOWN stop retains its new completion check and receipt but preserves the existing terminal cause and referrals, with no new terminal record, referral intent or decision-basis receipt member for that earlier stop. No result releases or consumes keys as a successful completion. No synthetic native event is generated. A found unique attributable record enters EFFECT_OBSERVED, not COMPLETION_CHECKED.

Deployment of a STOP_RETAIN definition initializes completion_checks, terminal_records and referrals as empty arrays; a definition with only referral_policy initializes referrals. Retain optional state.completion_checks, required and initially empty for a STOP_RETAIN definition. Rows are sorted uniquely by event_id and bounded to 128. A row is exactly `{check_digest,event_id,event_digest,permit_digest,authorization_digest,dispatch_digest,lookup,disposition,reason_codes}`. disposition is COMPLETION_FAILED. check_digest is digest("completion-check",the full row omitting check_digest). The receipt's optional completion_check_digest binds it. Its details are exactly [{kind:"COMPLETION_CHECK",check_digest,status:lookup.status,reasons:reason_codes}]; this new kind follows EFFECT and precedes CLOCK in the fixed detail order. The complete lookup is portable and restart-recomputed. This event produces no registry transition; its terminal record retains the prior permit reservation bases as provenance, not current registry roots.

## 4. Terminal and referral records without cycles

Extend step with optional referral_policy exactly `{authority,completion}`. Each is a sorted unique array of at most 16 routes. A route is exactly `{id,destination_role,queue,purpose,safe_state,via_role,requirement_ids}`. requirement_ids is a sorted unique bounded source-requirement filter; empty means every admitted authority withholding. Nonempty matches a failed SOURCE_OBSERVATION requirement_ref. For completion all routes have empty requirement_ids. via_role is null or the source-selected intermediary role. A safety referral names Safety Compliance Lead via Reliability Supervisor; it does not claim direct delivery. The declarations identify roles, queues, purposes and safe states only; they grant no authority to send a message.

A decision basis is exactly `{instance_id,event_id,event_digest,disposition,reason_codes,permit_digest,authority_result_digest,outcome_digest,completion_check_digest}` with nullable absent evidence members. decision_basis_digest is digest("decision-basis",complete_basis). Restart reconstructs this exact basis from the receipt and the unique retained outcome or completion check for its event_id; no separate decision_bases inventory is added. It refers only to already calculated event/result/outcome/check preimages, never to the next state or decision receipt. A receipt with terminal or referral records retains optional decision_basis_digest and terminal_digest. Ordinary receipt hashing then binds those independent records through state_after_core_digest, avoiding a cycle.

A terminal record is exactly `{terminal_digest,event_id,event_digest,instance_id,occurrence_id,permit_digest,authorization_digest,dispatch_digest,decision_basis_digest,cause,occurrence_status,evidence_digests,retained_reservation_bases}`. The latter copies the permit's complete budget_revisions, which identify the original reservation results, not current roots. cause is UNKNOWN_COMPLETION, UNEXPECTED_COMPLETION, CONFLICTING_COMPLETION, DECLARED_COMPLETION_FAILURE, COMPLETION_LOOKUP_FAILED or NO_EFFECT_COMPLETION. occurrence_status is OUTCOME_UNKNOWN or BLOCKED_DISPUTE. evidence_digests is a sorted unique set of the exact relevant authority result, native evidence or completion-check digests. terminal_digest is digest("terminal-record",the full record omitting self). Retain state.terminal_records sorted by terminal_digest; at most one initial stop record per occurrence, bounded to 128. Late facts never alter the retained cause.

A referral intent is exactly `{referral_digest,event_id,event_digest,instance_id,occurrence_id,decision_basis_digest,terminal_digest,cause_digest,destination_role,queue,purpose,safe_state,via_role,evidence_digests}`. terminal_digest is null for admitted authority withholding and the exact retained terminal digest for completion failure. cause_digest is the full authority-result, outcome or completion-check digest selected by that decision. referral_digest is digest("referral-intent",the full record omitting self). Retain state.referrals sorted uniquely by referral_digest, at most 4096 records and at most 16 per decision. Every selected route is retained in the same lifecycle transition as its cause, receipt and replay. Limits refuse before any partial mutation. Delivery, queue persistence, receipt and resolution remain separate host records with no effect on work permission.

A definition containing any nonempty authority referral routes initializes state.proposal_authority_evaluations as an empty array. Every admitted PROPOSE/WITHHELD with an AUTHORITY detail in that definition retains one closed row exactly {evaluation_digest,event,authority_result,authority_result_digest}. event is the complete original PROPOSE event, including its full authority_input, budget_inputs, executor, selected clock and original expected state bindings. authority_result is the complete independently evaluated refusal; authority_result_digest is digest("authority-result",authority_result). evaluation_digest is digest("proposal-authority-evaluation",the complete row omitting evaluation_digest). Rows are sorted uniquely by event.event_id and bounded to 128. The receipt retains proposal_authority_evaluation_digest, and referral evidence_digests includes this digest and the full authority-result digest. Definitions without authority referral routes retain no such carrier. Restart reevaluates the complete original authority input at its retained selected clock and recomputes the proposal/event digests, result, receipt details and selected referral filters. The row must match the original receipt event, occurrence, executor, expected prior revision and state digest. Missing, extra, substituted or rehashed semantically invalid rows fail state admission. Limits refuse before partial mutation.

Admitted PROPOSE/WITHHELD and gated AUTHORIZE_DISPATCH/WITHHELD use authority routes. Fresh gated authority_result and authorization_evaluation remain complete; referral evidence_digests includes both. A refused malformed/binding input creates no governed referral; the host may retain a separately declared external boundary referral. Protected failure evidence and collision owners are not agent-facing data. Completion terminal failures select every completion route and retain full cause evidence. Readback returns declarations and governed portable intents only under the existing host authority boundary.

## 5. Boundary declarations

Extend definition with optional boundary_exits, a sorted unique array of at most 16 `{id,scope,owner_role,queue,purpose,safe_state,reentry_requirements}` declarations. scope is PHYSICAL_CONTROL or MIXED_CONTROL. Equipment scopes prohibit both register update and physical command and identify Operations Control Room Lead. reentry_requirements is a sorted unique array of source-selected descriptive identifiers for new request, separate control procedure and new approval; these strings provide no executable English predicate.

A host boundary referral record is exactly `{referral_digest,definition_digest,exit_id,request_digest,scope,owner_role,queue,purpose,safe_state,evidence_ref,provenance_digest}`. The digest uses boundary-referral over the complete record omitting referral_digest. check-evidence can validate this record against the exact definition/exit and request digest; it creates no lifecycle state. The closed check-evidence input is exactly `{profile:LINEAR,role:REVIEW_EVIDENCE,specification_pin,definition,definition_digest,request_digest,boundary_referral}`. The definition is admitted under the current pin; both definition digests and both request digests must agree. Every selected exit field must match exactly. provenance_digest is digest("boundary-referral-provenance",the complete record omitting provenance_digest and referral_digest); referral_digest then hashes the complete record omitting referral_digest. A successful result is exactly `{status:EVIDENCE_VALID,profile:LINEAR,role:REVIEW_EVIDENCE,specification_pin,kind:BOUNDARY_REFERRAL,definition_digest,request_digest,referral_digest}`. Semantic mismatch uses the existing EVIDENCE_INVALID/BINDING_MISMATCH result; shape refusal uses the existing prestate REFUSED/SCHEMA_INVALID result. This validates binding only; it does not authenticate classification or request contents. The host must select the request's boundary classification under declared authority; a model assessment may advise, but does not grant a physical command or register authority. No actual referral delivery occurs in this apparatus.

## 6. Integrity and verification requirements

Schema/canonical admission, exact candidate/profile/definition/state, replay, expected revision, event/permit/dispatch binding and selected current clock precede completion policy. Full source-selected completion declarations are admitted statically; no known valid fault can fall through to the inherited completion path. An existing stopped or complete instance admits attributable late native evidence conservatively but never new work. Effects and reservation results remain one atomic transition, with terminal/referral records and the canonical request/response log committed at the same expected roots. Lookup failure changes work/terminal/referrals only and leaves the registry unchanged. A failed commit leaves all authoritative prior roots and the event log in force.

Restart recomputes every new digest, full required completion field comparison, provider identity duplicate/conflict classification, lookup binding/eligibility/coverage/status, the exact observed authorization claim and prohibited-dispatch receipt, decision basis, original terminal cause and exact selected referrals, with receipt/replay/state roots. It preserves an admitted claim-only lookup without reconstructing a nonexistent authorization and requires a BLOCKED_DISPUTE occurrence to remain blocked in its terminal record and later state. A self-consistent top-level rehash cannot make an unreachable checkpoint valid. Provider truth, authoritative history, lookup completeness, authentic remits, source fidelity, production durability and external-writer exclusion remain host or review premises.

Required vectors include all eleven equipment fields and each individual omission/type/value/link/time fault; provider identity changes, changed bytes and duplicate receipts; each lookup outcome and boundary, incomplete/stale/forged/provenance/dispatch faults, candidate overflow/reordering/duplication; prior safe versus possible send; no resend/release or routing after terminal stop; both completion destinations; filtered safety referral via the supervisor; late exact settlement without reopen and late conflict preservation; restart rehash attacks and atomic commit failures. Neither consumer supplies expected bytes.

Generated-field vectors include omitted versus empty declarations, exact variable values, missing/extra/duplicate fields, unknown or wrong nominal type, malformed scalar, declaration overlap and ordering, the combined field limit, full projection and restart reconstruction, changed provider facts, and exact prior-effect transfer from a generated field. No vector treats an arbitrary typed disposition or warning string as proof of filing acceptance.
