# External dependencies and host obligations

Identity: `seampoint.work-class/1.0.0-draft.2/external-dependencies`. Status: `DRAFT_NOT_ADOPTED`, `APPARATUS_ONLY`.

The work-class contract accepts facts from systems outside the deterministic consumer. These facts are inputs with explicit bindings and failure behavior. They are not inferred from names, credentials, provider reputation or local time.

| Boundary | Responsible party | Required control | Evidence supplied to the consumer | Failure behavior | Deployment verification | Residual limitation |
|---|---|---|---|---|---|---|
| Organizational policy and authorization | Policy owner and authorizing organization | Approve the exact work-class revision, budget definition and authority roots | Authorization record bound to subject digests, with the attributable return defined in WCS2-006 | Refuse deployment or return `AUTHORITY_REQUIRED` | Check subject, revision, approver and validity against the organization’s control system | The consumer cannot decide whether an organization’s policy is legitimate. |
| Identity and credentials | Identity provider and host | Authenticate the actor and bind the credential to the exact executor and occurrence | Credential record with provider, subject, validity and revocation evidence | Refuse the operation or return `DEPENDENCY_MISMATCH` | Verify the provider assertion and protected credential channel | The reference consumer does not authenticate a person. |
| Observation truth and freshness | Observation provider and host | Obtain a complete, attributable snapshot or statistic at the declared revision | Provider, source, query digest, revision, coverage and evidence reference | Return `OBSERVATION_UNAVAILABLE`, `OBSERVATION_STALE`, `OBSERVATION_CONFLICT` or `OBSERVATION_INCOMPLETE` as specified | Verify provider attestations, retention and nonrollback policy | A syntactically valid observation can still be false. |
| Clock | Host clock service | Supply an authentic source-matched instant at the declared precision and retain accepted revisions; register any host-selected source before another event relies on it | Clock event with source, status, instant and revision | Hold or return `CLOCK_UNAVAILABLE`; do not advance state | Compare the source and revision to the controlled clock service and verify the relying event selected the required authority, permit, deadline or registry source | The consumer accepts a syntactically valid new source and cannot measure real time or authenticate that source without the host control. |
| Durable state | Runtime host | Atomically install one authoritative initial root per organization and instance, then commit each complete next state and receipt before dispatch | Durable deployment namespace record plus state bytes, digest, receipt and revision | Refuse a conflicting duplicate deployment or dispatch from an uninstalled or uncommitted state; never assume no effect | Concurrent-deployment, crash and restart tests against the selected storage system | The in-memory host proves uniqueness and commit behavior only within one process. |
| Durable event record | Runtime host | Commit the complete canonical lifecycle request and response preimages with the state transition before dispatch, keyed by the event, decision and transaction digests retained in state | Append-only event-log entry containing canonical request bytes, canonical response bytes, event identity and digest, decision digest and transaction digest | Treat failure as commit failure; do not dispatch or claim a complete audit record | Recompute every retained digest from the log and verify ordered recovery with the state checkpoint | State alone is an execution checkpoint. Without the host log, its digest commitments do not reconstruct withheld inputs or other complete event preimages. |
| Native dispatch | Connector host | Dispatch only the committed, authorized actuation identity before the declared permit expiry and preserve the provider result | Dispatch identity, provider outcome, event time and evidence reference | Retain `UNKNOWN` or disputed exposure and block unsafe redispatch | Exercise permit-expiry enforcement, connector idempotency and effect reconciliation | The consumer cannot prove what an external system did or bound the proposal-to-dispatch latency. |
| Single-process serialization | Reference host | Serialize initial-root installation and state transitions, enforce one organization-and-instance namespace, and compare the expected revision | Host deployment result, lock/transaction record and returned next state | Return `INSTANCE_OCCUPIED` for a conflicting duplicate deployment or refuse a stale transition without changing state | Run duplicate-deployment, two-client contention and exact replay tests | This does not qualify durable or distributed coordination. |
| Distributed coordination | Deployment owner | Provide one serialized writer for each organization-and-instance namespace and for each reservation registry, enforced by an atomic expected-revision comparison before commit. A row lock or serializable transaction on the state row, a conditional write keyed by revision, or a single-partition ordered log each supplies it. This candidate requires no cross-namespace or cross-registry atomicity. | Store transaction and fencing evidence bound to organization, instance and state revision | Refuse deployment or transition when coordination is unavailable | Test concurrent deployment, failover, fencing and split-brain behavior | Distributed execution is outside this candidate. |

Each active `CLOSED_DOCUMENTED_BOUNDARY` record binds the exact candidate and pin, affected paragraph and requirement identifiers, one typed responsible party, the required control or integration, evidence format, failure behavior, deployment verification method, what the record establishes, what it does not establish and the residual limitation. Its scopes must agree exactly with the coverage inventory. A boundary record closes the specification's description of what a host must supply. It does not turn a deployment obligation into a semantic qualification result or prove that the external fact is true.
